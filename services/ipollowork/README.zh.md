# iPolloWork 服务

[English](README.md) | 中文

独立的账号、组织、项目和计费服务。Node 提供 API 和管理界面，PostgreSQL 管理身份与事务记录，私有阿里云 OSS 管理生产文件。服务不引入 DSH 或旧 iPolloWork 运行时。

## 运行

使用 Node 24.15 或更新版本，以及 PostgreSQL 15 或更新版本。创建专用数据库和账号，将 `.env.example` 复制为 `.env`，设置 `DATABASE_URL`。升级时保持原 `DATA_DIR` 和认证密钥。

~~~sh
npm ci
npm run build
ADMIN_PASSWORD='set-a-strong-password' npm run admin -- admin@example.com 管理员
npm start
~~~

打开 http://localhost:4785。登录页支持注册，首位管理员只能通过本地运维命令创建。配置 `MAIL_WEBHOOK_URL` 和 `MAIL_WEBHOOK_TOKEN` 后支持验证与账号恢复。经过认证的 Webhook 接收 `{to, template, url}`。没有邮件配置仍可登录，但邮箱验证和密码恢复会报告未配置。

## 数据与部署

[存储与部署](docs/storage.md) 说明 PostgreSQL 迁移、备份、OSS、配额及保留规则。元数据包括用户、组织、部门、权限、项目、文件版本、精简项目记忆、订单和不可变积分账本。大文件及记忆版本正文存入对象存储。不会自动上传输入文件、完整本地对话或原生工作区状态。

个人未发布的输出保留七天，已发布项目的输出及组织输出持续保留，直到明确删除。云端清理不删除本地原生文件。默认个人容量 200 GiB、组织容量 500 GiB，管理员可单独调整。配额是允许使用的容量，不是预分配空间，也不代表免费流量。

`compose.yml` 提供 PostgreSQL 与服务的持久卷。设置 `POSTGRES_PASSWORD` 及 HTTPS `SERVICE_ORIGIN`，数据库不对公网开放。公网部署默认必须使用 OSS；本机开发未配置 OSS 时使用服务自己的私有缓存。[阿里云部署](deploy/README.zh.md) 增加自动 HTTPS 和限定权限的 ECS 存储身份。原生会话中继的连接由单进程管理：虽然 PostgreSQL 支持并发连接，本版本仍使用一个中继实例，不应将独立中继进程放到轮询负载均衡后。

## 账号与权限

用户可个人使用，也可创建组织。组织所有者和管理员管理部门、邀请、成员、文件包、Skills、插件和组织模型。邀请绑定邮箱且会过期。每次请求检查当前成员关系和授权，调换部门或移除成员后，访问范围随之改变。

项目属于个人或组织。View、Participate、Maintain 权限可授予当前成员或部门。维护者管理访问并接受贡献。接受时同时核对项目版本与文件基础版本，冲突时保留提案。历史快照和旧结果记录仍可读取，已停用的快照、评论、结果写入接口返回 HTTP 410。

## 原生 DSH 连接

将套件 `accountOrigin` 指向本服务。凭据保留在 DSH 原生凭据库中。套件只在已关联项目中监听原生 `deliverables/presented` 事件，流式保存输出版本，不改变 agent loop（智能体循环）。停用套件会移除这些订阅和模型上下文补充，本地文件及会话仍然保留。

`GET /api/v1/projects/:id/space` 返回已接受状态，`/overview` 返回参与者和贡献数量，`/artifacts` 返回当前输出版本。原始文件流上传到 `/artifacts/upload`，元数据通过 `x-ipw-artifact` 头传递。该接口拒绝输入文件。输出默认上限为 512 MiB，可通过 `MAX_ARTIFACT_BYTES` 调整；普通资源上传仍限制为 24 MiB。

记忆贡献只包含提炼后的事实与决定。维护者明确合并完整摘要，最多 8,000 字符和两级标题。正文与已接受版本保存为私有对象；PostgreSQL 保存当前精简摘要，供下一轮模型使用。服务不会后台调用模型挖掘完整对话。关联项目的维护者也可通过套件项目记忆工具合并。

## 分享

套件使用 DSH 原生分享弹窗和查看器。链接允许匿名访问，组织分享可指向整个组织或其部门。会话权限与 fork 开关仍由原生机制管理，分享不修改项目授权。服务检查所有者会话与当前接收范围，通过向外建立的 WebSocket 中继原生消息，分享电脑必须保持在线。中继仅在内存中处理流量，不保存对话或模型密钥。

沙箱查看器仅获得短期分享凭据，不能读取账号 Cookie。查看器资源允许隔离后的不透明来源加载与 Cordis 配置求值；账号页面保留同源资源策略且禁止动态求值。撤销会取消访问，停止的分享保留撤销记录。`TRUSTED_PROXY_IPS` 仅填写准确代理 IP，并让代理覆盖 `X-Real-IP`。不记录授权头或分享凭据路径。[代理示例](deploy/nginx.conf) 包含 HTTP 与 WebSocket 配置。

## 官方服务与套餐

[官方计费](docs/billing.md) 说明模型预设、价格来源、积分换算和启用条件。管理员在服务中心集中配置 Key，插件可选择官方服务或自己的原生 Key。缺少凭据不会自动切换到付费通道。

每个服务商的各项能力共用一个 Key 配置。百炼包含千问及第三方的主力语言模型，编辑器默认显示推荐版本，并支持搜索完整的已保存目录。模型同步会导入对应地域所有厂商的目录和可识别的官方价格，保留管理员编辑的价格，新发现的模型保持停用。价格编辑支持输入输出 Token、缓存、图片张数、音视频时长、字符数和价格阶梯。未配置、停用、未定价及价格过期的模型不进入用户目录，详见[升级步骤](../../docs/upgrade-guide/v0.2.2-rc.2/ipollowork-model-pricing/guide.zh.md)。

网关认证每次请求，限制路径与模型，原子预占积分，并按供应商用量结算。视频查询验证任务所有权，重复请求 ID 不会重复扣费。结果未知时保留预占，直到管理员向供应商核实，不会盲目重试。响应可在 24 小时内重放，每个账号同时只允许一个执行中的网关请求。

Stripe、支付宝和微信支付仅在供应商通知验签通过或服务端查询确认后结算。支付凭据在后台集中配置，未配置的渠道不能创建订单。附带两个停用状态的 30 天会员草案，不启用自动续费。现金价格与积分兑换价格独立，启用套餐必须满足配置的成本底线。会员限额和周期用量详见[计费说明](docs/billing.md)。

## 验证

~~~sh
TEST_DATABASE_URL=postgresql://127.0.0.1:5432/ipollowork_test npm run check
npm run build
npm run bench:database
~~~

测试使用独立数据库 Schema，覆盖真实 Better Auth 请求、组织授权、支付重放与退款、并发配额、输出版本、保留规则和用量结算。[容量报告](docs/capacity.md) 记录了包含 500,000 个模拟账号的可复现 SQL 工作负载，不是同时在线用户容量保证。

服务目录按 `language`、`image`、`video`、`audio`、`embedding`、`tool` 分类各连接及模型，另有 `vendor` 标识供应商。旧记录根据已声明能力归类，不猜测模型名称。非语言模型无需 Token 上限字段，组织服务的非对话操作必须明确声明接口路径，同一份分类连接用于部门和成员授权。
