# iPolloWork Video Compose

Use the saved storyboard, current entry and design/media/audio constraints. Storyboard, Voiceover and Soundtrack own their phases; existing artifacts do not request reloading them. Boundaries are in [video.md](video.md).

## Recipes and components

Reuse known choices/catalogs. Initial/structural assembly reads needed `core-v1-index.md`, `core-v1-video/catalog.md`, `core-v1-video/motion/catalog.md` metadata and selected `motion/component-map.md` overlays. Shortlist at most three scene bodies and three mapped components. Layouts supply spatial slots; selected recipes implement the content's temporal actions, not responsive website/PPT roots.

Use `media/video_recipe_catalog` for locally installable native and Shotcraft recipes; query missing needs/`recipeCategories` once (`limit <=20`, paginate missing results only). Match intent/useWhen/avoidWhen, authorized inputs, capacity, event/reading order, landing and genre energy before appearance. Read selected local `recipe.md`, manifest and actual implementation before mounting; retain its working motion rather than rebuilding cards with entrance effects. Imports need exact card/variant and pinned source/preview; unported references/hosted links are not executable auditions. Missing cards require the actual manifest and disclosure.

Frame narrative records selected ID/card/variant, content fit/limits and visible action/landing. Note an alternative/tradeoff when consequential, not a manufactured backup for every shot. Comparisons retain shared criteria; lists are not causality. Respect explicit usage limits; overflow needs a meaningful split/different recipe, never truncation or tiny text.

During assembly set root `data-ipw-recipe-policy="recipe-first"`. Use a fitting recipe; when none fits the planned content/inputs/visual structure, author editable custom work autonomously unless the user prohibits it. Consider a compatible combination or meaningful split once; never distort the content, force a recipe match or impose a component proportion/scene count. Record real considered IDs and mismatches, why split/combine does not fit and minimal custom scope in frame narrative/`custom_reason`, `data-ipw-component-decision="custom:<specific structural reason>"`, and literal `data-ipw-custom-recipe-evidence` JSON with `candidates` (1–3 `{componentId, limitation}`), `splitOrCombine`, `minimalScope`. Failed installation/phrase binding is an implementation defect to repair, not evidence of semantic no-fit. Missing catalog/install is a capability gap to report, not permission to fabricate reuse. Under recipes-only set `data-ipw-recipe-policy="recipes-only"`: use another validated recipe, split or report the gap; original graphics with a recipe label fail that policy.

Install selected IDs in one bounded `ipollowork_extension_call` (`extensionId=media`, `action=video_component_install`, `args={sourcePath:"video/<exact-project-id>/index.html",componentIds:[...]}`). Prefer resolved `instances`: unique `sceneId`, `componentId`, `start`, `duration`, `timingSource`, actual content and event timing. Narrated instances read [Measured recipe bindings](video-voiceover.md#measured-recipe-bindings) and use Voiceover's measured event map; `cueTimes` is for measured non-speech cues, not guessed phrase alignment. Mount returned `instances[].snippet`; defaults are planning, not speech alignment. Read selected `motionRecipe.usage` and `shared-contract.md` once; preserve edited component copies, repair asset/capacity/cue conflicts. Retain returned `data-composition-src`/recipe paths, `data-ipw-registry-component`, host timing, unique `data-composition-id`, stable scene IDs, literal `data-variable-values`, `data-motion-pattern`, `data-ipw-timing-source` and executable `data-ipw-beats`. Adapt real native motion/content/tokens to measured windows; reconcile storyboard after reordering.

## Visual production and media

After the storyboard is saved and production is in scope, read only selected recipe parameters/pitfalls, confirm obtainable inputs and revise affected fit before installation. For substantial visual work establish 2–3 inexpensive representative opening/densest/landing styleframes after saving the storyboard; use existing assets/editable elements, final dimensions and shared type/palette/safe margins. Save paths or a justified skip in first-frame notes. This is direction evidence, not another composition or approval step; script-only work describes it.

### Acquire and mount visual assets

- Use one concrete query per distinct visual need: subject + action + setting, date/location when factual, optional language equivalent and exclusion criteria. Reuse identical needs; no fixed keyword quota. Verify source relevance, provenance and license. Exact data/mechanisms need editable graphics rather than loosely related B-roll.
- Derive `asset_brief` from subject/identity + environment + action/change + framing/camera + semantic timing + final state + style + needed sound, omitting irrelevant parts and honoring the model's actual capabilities and duration limits. Each supplied reference must have an explicit role (identity/product, setting, style, first/last state, motion or audio), exact project path, what to preserve and what may change. Resolve conflicting references from user priorities; ask only consequential ambiguity. Preserve recurring identity/product details, location geometry, palette and screen direction. Never invent @reference syntax, unsupported upload/audio or factual claims from a reference.
- Reuse local/supplied assets first. Generate imagery for needed missing content; generate footage when subject motion is necessary and cannot be expressed by available components/assets. Do not call a video model just to pan a still. Use images/footage as meaningful focal subjects, distinguish illustration from evidence, and retain attribution/source metadata.
- For factual/news work read sources with available search/browser tools, verify event date and media relationship, then import actual media. Save publisher/URL/date/attribution in `asset_origin`/notes. An identified article screenshot may establish provenance; its page URL is not a media file. Missing relevant footage needs truthful source material/data/labelled illustration and disclosure. Do not invent search tools, URLs, licenses or downloads. Research/import is allowed browser work; composition preview remains host-owned.
- For real-page/camera scenes capture sharp full-page texture, semantic cutouts and clean backplate where required. `assets/capture-layout.json` records viewport, pixel ratio, page height and element CSS-page `{x,y,w,h}`; overlays/destinations share those coordinates. Wait for fonts/state, freeze/anonymize personal/live data, verify dimensions and recapture only changed regions. Use the appropriate device/desktop surface; output size/pixel ratio examples are not quotas. Preserve supplied interface geometry/state. When editable UI is required, recreate the observed screenshot/page faithfully in HTML with native tokens/variables and label a reconstruction honestly; never invent product controls or present an animated cursor as recorded interaction. Actual product demos reuse available browser/media capture on the real page: show the action and observable result, retaining sharp context/highlights and real state transitions. This is media metadata, not another storyboard/runtime.
- Before initial visual production call `media/artifact_media_review phase=plan` with exact workspace-relative entry and stable `id`, `purpose`, `kind=image|video|reuse|diagram` for all useful needs; an empty plan needs supported exemption/reason. Reuse its capability result; choose one compatible authorized model per operation. The storyboard owns story/choices, host `brief.json` owns capability/outcome/job state. Submit independent assets as one bounded batch or in parallel when supported while continuing independent scene work. Query uncertain-job status/recovery before retrying.
- Save verified results in project `assets/` and use project-relative paths. Generated copies preserve original receipts and original workspace-relative `generationPath`. Mount the real visible `img`/`video` `src` or `poster`, consistent with component variables and owning HTML path; a JS value or hidden dummy is not a mounted image. `phase=check` records every planned outcome and actual HTML-referenced `path`; generated receipts verify copied bytes. Pre-existing files are reused. Missing/pending needs require resolution; unavailable/failed/declined needs need truthful reason and delivery-scope disclosure. Verify response type/signature, format/dimensions/duration/placement; HTML/JSON is not media. Use exposed providers/credentials, never an external authenticated CLI substitute. File/receipt checks are not visual or audible evidence.

## Composition and timing

- Load explicit GSAP (prefer packaged local `gsap.min.js`, no async/defer before inline calls), initialize `window.__timelines = window.__timelines || {}` and register the paused timeline under the root ID; Studio does not supply missing globals. Repair syntax/dependency errors. Keep project width/height/viewport/CSS stage/aspect ratio unless a format change is requested. Use local `assets/ipollowork-logo.svg?v=20260729` fallback while preserving supplied third-party brand/placement. Every visible editable element needs stable unique class/id/data-hf-group for inspector selection.
- One authoritative root owns composition identity, declared stage/aspect ratio, FPS, duration, tracks and registered paused GSAP/HyperFrames timeline. Preserve stable hooks and unique IDs. Theme tokens own palette/type/graphic language, not timing/tracks; intentional target geometry replaces responsive viewport reflow.
- Every full `.scene.clip` declares `data-ipw-scene`, frame-aligned window/track, motion pattern, accepted timing source and literal executable beat map. Use [motion principles](video-motion-principles.md#executable-beats) for the exact beat/motion schema. Full scene windows meet continuously. Each mounted snippet preserves `data-ipw-timing-owner="host"`; parent sets the real duration and the component holds Land until host ends, without competing inner clip windows.
- After structural edits synchronize root/scenes/clips/transitions/captions/audio/animation from one integer-frame schedule (`frame / fps` with necessary precision). Theme-only/unrelated edits preserve timing. Scope selectors to the actual scene instance; all motion/holds fit its window. Direct/reverse seek, replay and export must show identical states without prior-frame history, wall-clock timers, random values, ambient CSS loops or independently running timelines. Prefer transform/opacity and avoid layout thrashing. Ordinary existing-element motion discovers `list_motion_presets` for correct targetKind, then `mutate_motion` on exactly one stable selector with explicit start/end, returned preset ID, declared parameters and one enter/emphasis/exit phase. Replacing a phase is intentional; never stack same-phase presets or rewrite supported effects in GSAP. Voice-transcribed requests use this same interface.
- Every scene after the first declares incoming transition/duration/narrative intent. Intent is exactly `continue`, `topic-change`, `time-change`, `location-change`, `compare`, `reveal`, or `closure`. Custom incoming beat begins at 0. Use zero-duration `cut`, a supported preset through `mutate_motion`, or narrow `custom:<id>`. Custom handoff stores literal `data-ipw-transition-handoff` (`fromSceneId`, `outgoingResult`, `incomingSubject`, `continuity`, `visualAction`, `target`), matching `data-ipw-animation-reference`, and an incoming beat with that same reference/motion finishing inside the transition interval. Run inside the incoming scene, not overlapping full windows or fading outgoing to blank. Source declarations do not prove rendered continuity.
- For intentional continuity, mark the actual persisting visible element `data-ipw-carrier`; only scenes requiring cross-beat carry declare `data-ipw-continuity="required"`. Preserve the same DOM identity and meaningful geometry through handoffs. Matching names/replacement nodes are not continuity; deliberate cuts/reading holds remain valid.
- Camera follows a real subject/action from orientation through a meaningful waypoint to its result; keep framing continuity and settle for reading. Use mapped recipes: `camera: component:spatial-camera-suite#<shotStyle>` installs the actual `shotStyle` (`graze-face-tour`, `depth-layer-moves`, `spotlight-hero-card`, `runway-ground-skim`, `steep-tilt-glide`, `subject-follow-track`, `container-morph`, `gather-lockup`). Otherwise use native screenshot/device framing or a discovered `camera.*` preset on the actual wrapper through `mutate_motion`; retain its note/reference. Keep captions screen-fixed and one camera owner. `device-carousel` optionally uses `carouselMode=flow-belt` for a continuous product stream; existing defaults remain. No compulsory 3D, whole-film one-take or decorative orbit; a beat-map name is not execution. For fast generated motion, host render accepts `motionBlur:true` (180° shutter, four subframe samples in linear light). Default projects remain unchanged. Set requested `fps`/`resolution` explicitly; inspect action/contact frames instead of an always-on CSS blur.
- For requested music-led motion, use the measured saved cues supplied by Soundtrack; read only [Measured cues](video-soundtrack.md#measured-cues) when analysis or rebinding is needed. Do not infer cue timing.
- Components and custom scenes use the active `design-tokens.css` and `--ipw-*` palette/type/graphic tokens. Keep static `data-composition-variables` aligned with manifest IDs and meaningful editable content/style values; preserve editable nodes/labels/connectors/data, stable IDs, brand assets and selection hooks. Later design-system/theme/token changes preserve variable bindings, assets and timeline; do not hardcode the theme into every scene or flatten editable explanations into imagery. Readability/overflow/overlap repairs retain native editable meaning. Framework owns playback/audio sequencing; never mute or replace tracks to conceal a preview defect.

## Phase handoff and acceptance

Prepare scene anchors/marked visible transcript before authorized synthesis; measured narration drives event bindings and dependent timing. Otherwise retain the genuine silent/media/music driver. Mount real snippets/media and reconcile storyboard IDs/status/windows. Save source for the client's single delivery continuation; applicable [acceptance](video-acceptance.md) inspects current ordinary-speed evidence, never another model-owned review/render loop.
