# HyperFrames Video Rules

Use only the active session's exact project, runtime, media actions and editor contract. Read the sections needed for this task; a targeted edit does not require the full production guide. Shared scope/content, layout and media decisions live in [shared guidelines](shared-guidelines.md), sections 2–3, 5 and 7. [Motion principles](video-motion-principles.md) owns temporal grammar and executable beats; follow `video-acceptance.md` as the single owner of the final verdict.

## Session and execution boundary

- Read the confirmed brief, current `index.html`, template metadata, `design-tokens.css` and existing assets. Keep all changes in the current `video/<session-id>/` project and save its exact entry. Never create a parallel project/preview server, restart app-owned services, stop shared Node processes, install global Skills/packages or change the bundled runtime.
- Preserve unrelated user-authored scenes, media, fixed-brand assets, editor hooks and stable IDs during follow-ups. Manual `data-hf-id`, `data-hf-studio-*`, `--hf-studio-*`, inline geometry/transforms and GSAP position/scale/rotation are user-owned; change only explicitly requested element/properties. Immediately before a whole-file write re-read and merge current disk bytes, never a cached HTML snapshot. Do not enumerate/read sibling projects to resume work; use the current transcript and exact entry. Never delete or truncate `index.html` or tokens before replacement is complete: update once or atomically rename a prepared sibling. Interrupted edits must leave the last valid entry.
- Reuse known capabilities, selected catalogs and completed validations. Discover missing actions once; inspect an actual schema once after a tool failure and make one corrected retry. A repeated failure leaves an unfinished draft with its exact blocker. Never invent providers, fields, paths, licenses, downloads or successful evidence.
- Save the complete composition once; the client owns the aggregate component/project/voiceover delivery gate and its bounded repair continuation. Do not start an additional validator, review render or preview loop from the model turn. Run a supplied CLI inspection/render only when the task delegates it; use the exact bundled command and project, bounded checks, and report the validating command. Fix diagnostics rather than bypassing them.

## Plan content and storyboard

1. Inventory source claims, steps, figures and qualifications once. In existing frame narrative keep `point ID → source heading/page/paragraph → frame(s)` → spoken or visibly explained evidence. Without source files trace brief requirements instead; never invent source anchors. Preserve names, numbers, units, causal relationships and meaningful parentheses/qualifiers. Record intentional omissions and unresolved source gaps. Preserve required facts and explicit user caps: an irreconcilable cap needs one user choice, not silent deletion or rushed speech.
2. Identify the driver: speech, dialogue, visible action, music, footage or silent reading. Choose intended audience change → observable event/evidence → executable recipe intent/input/capacity → motivated framing. Write narration first for speech-led work; do not force it onto visual- or music-led work. Keep process dependencies readable; compare at matching viewpoints and scales; spatial travel serves spatial relationships. Decide readable holds before motion. A library match or attractive stock clip is not evidence of fit.
3. Shortlist executable recipes by intent, input and capacity using the recipe section below. Bind events in causal/viewing order to subject/action, required input, result/hold and exact spoken phrases, dialogue turns, media moments, music cues or silent reading. Adjacent phrases may share a visual event; one sentence may span events. Record a compact provisional beat map for substantive shots, without making every clause a new animation.
4. Make one rough narration-duration estimate per shot, about 4 CJK characters or 2.5 Latin words per second plus purposeful reading holds; otherwise use action/media/reading time. Use a single counting calculation only when needed. Approximate targets are not strict caps. Do not calculate per-word, per-phrase or frame-accurate timestamps before synthesis, repeatedly adjust near-identical prose, draw SVG coordinates, write a JS/Python timeline builder or schedule arbitrary four-second motion cadences during drafting.
5. Save the complete native `STORYBOARD.md` with positive estimated durations and `status: outline` before media acquisition or production. Combine source/semantic and saved-format checks into one post-save review: re-read the source and saved storyboard for coverage, qualifiers, fit and readable holds. This is agent semantic self-review, not a deterministic parser or rendered-quality verdict. Reopen only affected shots when user edits, failed checks or measured media introduce evidence.
6. Continue automatically after the saved script into production. Pause only for an explicit script-review or script-only request; never repeat supplied confirmation. Script-only work saves the script without media generation or composition edits. Content determines scene count and duration; template examples are not quotas. Respect explicit maximums; do not add filler or omit content to match samples.

### Native editable script

Use the existing Studio `STORYBOARD.md`, not another JSON plan, document or independently edited transcript. Put whole-video settings in leading `---` frontmatter. Each shot field is a separate `- key: value` line under `## Frame N — Title`; no semicolons, translated keys or Markdown pipe tables. Do not put a code fence around the saved file. Keep extended direction/beat maps in narrative paragraphs after metadata. Omit unset optional fields rather than literal `omit` or `null`. Re-read the saved file: every frame needs non-empty `scene`, positive `duration` and its actual status.

Native parser example; save the content inside the fence, adapting facts and shots:

```markdown
---
format: 1920x1080
message: Turn an idea into a working team
audience: Independent founders
theme: ai-auto
music_prompt: Restrained instrumental pulse beneath narration
---

## Frame 1 — The idea takes shape
- scene: An idea card becomes a three-step plan; the focus moves to the first task.
- duration: 5s
- voiceover: One idea becomes the next clear step.
- camera: fixed:progressive-build
- transition_in: cut
- asset_source: code
- asset_brief: Editable idea and task cards; no external visual required.
- status: outline

0–1s establish the idea; 1–4s reveal and connect tasks; 4–5s hold the first action.
```

| Scope | Fields and meaning |
| --- | --- |
| Whole video | Audience, purpose, genre, format; `theme: "ai-auto"` derives direction while preserving Work tokens, or use the manually selected theme ID; `visual_style`; one supported `motionStyle`; `music_prompt` direction and the actual project-relative `music_asset`. |
| Shot | `scene`, `duration`, `transition_in`, `status: outline`; `voiceover` only for spoken text; `speaker` only when character/dialogue identity matters. `voice_id`, `voice_model`, `voice_name` select a library voice; `voice_id: auto` delegates authorized choice, empty inherits the project default. |
| Production | `camera` resolved to a concrete treatment (fixed/local reveal is valid; no final AI-decides/basic placeholder); `asset_source` = `auto`, `existing`, `search`, `generate`, or `code` for editable graphics; `asset_kind` = image/video or omitted for AI choice; `asset_brief`; `asset_origin` for source URL/attribution or illustration description; `asset_reference` for exact local project media; `sound_effects` for event/time and `sound_effect_reference` for exact local audio. `music` is a deliberate shot override. |
| Recipe | `recipe` = exact executable component ID; `recipe_intent` = why it serves this audience event; `scene_id` = exact installed scene ID. Custom shots omit recipe and use `custom_reason`. Mount/validation status is inspected from actual sources, never authored as a claim. |
| Narrative | Coverage, fit rationale/limits/alternative, Establish/Develop/Land, relative energy, provisional beats, handoff, asset reference roles, sound and QA sample positions. Keep this in frame prose rather than adding schema keys or another sidecar. |

The script table edits this same file. Read its latest saved version before applying; preserve pinned media/music/effects/voices. Row save/reorder alone does not rebuild the film. During generation/apply match existing frames by `src`, not prior row number; add `src` only for a real built subcomposition, never the whole root as every frame's source. Advance outline → built → animated only after implementation exists. Reuse existing `SCRIPT.md` for long narration when necessary; maintain one authoritative transcript. Replace estimates with measured speech/media timing before assembly.

Subject/fact corrections propagate through affected script, actual spoken audio, rendered text, imagery and captions. Regenerate changed narration, retime dependencies and preserve unrelated work. A corrected picture/logo with obsolete speech is incomplete; a favicon is branding, not requested product evidence.

Shortlist at most three scene bodies and three mapped components. Video layouts supply spatial slots, not timelines, narration or responsive website/PPT roots. Choose the primary temporal pattern from the scene's verb; many-to-many overlays allow another supported pattern when implemented.

Use `media/video_recipe_catalog` for all locally installable native and Shotcraft recipes, querying narrative need or semantic `recipeCategories` with bounded pages (`limit <=20`). Filter intent/useWhen/avoidWhen, available authorized inputs, content shape/capacity, reading/narration order, final hold, visual direction and energy before appearance. Read selected local `recipe.md`, manifest and implementation only; cards are generated from owning manifests, not a second rule source. Imports require the exact card/variant and pinned source/preview; an unported reference or hosted preview link is not executable or an audition. If older distribution lacks cards, inspect its actual manifest and disclose the missing documentation.

For each frame record goal/visible change → selected ID/card/variant → concrete fit and limits → one credible executable alternative/tradeoff or honest no-fit → expected action/landing evidence. Do not copy generic catalog intent or manufacture a backup. A comparison needs shared criteria; an ordered list is not a causal mechanism. Respect explicit usage-count limits without imposing promo-wide once-per-effect quotas on teaching. Capacity overflow requires a meaningful split/different recipe, not truncation or unreadably small text.

During assembly set root `data-ipw-recipe-policy="recipe-first"`. Try a fitting recipe, compatible combination or semantic split before custom graphics. A structural semantic/input/capacity gap permits minimal custom work autonomously unless the user prohibits it; convenience, failed installation, phrase binding or cue fit does not. Record considered IDs and mismatches, why split/combine cannot solve them and minimal custom scope in frame narrative/`custom_reason`, `data-ipw-component-decision="custom:<specific structural reason>"`, and literal `data-ipw-custom-recipe-evidence` JSON with `candidates` (1–3 `{componentId, limitation}`), `splitOrCombine`, `minimalScope`. Missing catalog/install is a capability gap to report, not permission to fabricate reuse. Under recipes-only set `data-ipw-recipe-policy="recipes-only"`: use another validated recipe, split or report the gap; original graphics with a recipe label fail that policy.

Install all selected IDs in one bounded `ipollowork_extension_call` (`extensionId=media`, `action=video_component_install`, `args={sourcePath:"video/<exact-project-id>/index.html",componentIds:[...]}`). Prefer actual `instances` input with unique `sceneId`, `componentId`, `start`, `duration`, `timingSource`, real content values and truthful declared-event timing. Narrated instances use measured `narration` bindings below; `cueTimes` is for measured non-speech cues, never a substitute for provider phrase alignment. Mount returned `instances[].snippet`; defaults are planning, not speech alignment. Read selected `motionRecipe.usage` once (intent/inputRules/readingOrder/cueBindings/fallback/acceptance), preserve existing edited component copies, and repair missing asset/capacity/cue conflicts rather than truncating. Use returned `data-composition-src` snippets and returned project-relative recipe documentation; preserve `data-ipw-registry-component`, host-owned timing, unique `data-composition-id`, stable scene IDs, actual literal `data-variable-values`, `data-motion-pattern`, `data-ipw-timing-source` and executable `data-ipw-beats`. Do not recreate a selected component from memory. Read `shared-contract.md` once. Adapt content, tokens and native paused motion to the measured window; reconcile script fields with actual mounts after reordering.

### Sequence templates

Choose one fitting structure before detailed slots. A sequence assigns narrative jobs, energy/rest and continuity; a recipe implements a job; a transition implements a boundary. Record genre-appropriate relative energy and information density (hook/orientation → development/evidence → resolution/requested action), sequence/justified adaptations in the first frame's notes and slot/handoff in shot narrative. Names alone do not supply missing capabilities or prove execution. Teaching prioritizes dependency order and reading time; factual work preserves context/evidence, and quiet stories need not end in a sales CTA. Avoid compulsory slow motion, fast travel or once-per-preset quotas across genres.

| Sequence | Slots and fit limits |
| --- | --- |
| promo-energy-arc | Identity/orientation → focal product → distinct features with readable rests → supported payoff/requested action. Merge optional slots for short/single-feature films; no mandatory sales CTA for teaching. |
| concept-to-application | Question → definition/boundary → example → useful contrast/misconception → practical takeaway. Not a mechanism simulation; avoid repeated definitions. |
| mechanism-to-test | Phenomenon → supported dependent mechanism → worked case → test/prediction with conditions → resolution. Preserve reading time; lists/correlation are not causality; unsupported branching/feedback/simulation is a real gap. |
| compare-to-decision | Common task/criteria → paired evidence → tradeoffs/limits → conditional choice. Keep scales/units/viewpoints consistent; no unsupported winner. |
| task-to-outcome | Goal/start → dependent actions → observable checkpoint → result → relevant recovery/next action. Required real UI evidence cannot be fictional cards. |
| claim-to-evidence | Context/question → attributed evidence → supported meaning → limitation/alternative → bounded conclusion. Evidence gets sufficient reading time; generated illustrations/testimonials/source names are not proof. |

Only promo-energy-arc adapts [Video Shotcraft promo-energy-arc](https://github.com/Vincentwei1021/video-shotcraft/blob/main/references/sequences/promo-energy-arc.md), reviewed 2026-09-29, Copyright 2026 Wei Yihao, [Apache-2.0](https://github.com/Vincentwei1021/video-shotcraft/blob/main/LICENSE). Modified for HyperFrames, content-led timing and executable local slots. Retain attribution and vendored license. Other sequences are iPolloWork patterns. For a fitting 30–60s promo, upstream orientation 8–12%, focal subject 12–15%, features 55–65%, close 13–16%, and 2–4 optional breath cards are starting ranges: normalize one actual allocation, counting breaths within it, never enforce them on narrated teaching.

Assign each required slot a takeaway, real input, executable recipe and observable landing. Merge/omit optional slots with reason; preserve required facts. Reserve reading/rest during rough drafting, then quantize measured final windows to project frames. Allocate by semantic complexity, native motion ratios and minimum hold, not equal shares. Incoming transitions consume Establish time; they add no duration or overlapping full-scene windows. Count reading once: visual holds do not create silence. Explicit duration conflict needs a choice or meaningful split, not invented cues.

For each incoming shot note outgoing result → continuation/comparison/topic/time/location change/closure → incoming subject → recognizable anchor or intended reset → treatment/window. Preserve supported position/scale/direction/comparison anchors. Use one supported treatment per seam; a truthful cut is valid. If needed, narrowly animate existing subjects in a seek-safe custom handoff rather than drawing replacement content. Avoid competing entrances, stacked transitions, empty fades or obscured final qualifiers. Review outgoing Land/boundary/incoming Establish together within the acceptance batch.

## Production, media and sound

After script release, read only selected recipe parameters/pitfalls, confirm obtainable inputs and revise affected fit before installation. For substantial visual work establish 2–3 inexpensive representative opening/densest/landing styleframes after saving the storyboard; use existing assets/editable elements, final dimensions and shared type/palette/safe margins. Save paths or a justified skip in first-frame notes. This is direction evidence, not another composition or approval step; script-only work describes it.

### Acquire and mount visual assets

- Use one concrete query per distinct visual need: subject + action + setting, date/location when factual, optional language equivalent and exclusion criteria. Reuse identical needs; no fixed keyword quota. Verify source relevance, provenance and license. Exact data/mechanisms need editable graphics rather than loosely related B-roll.
- Derive `asset_brief` from subject/identity + environment + action/change + framing/camera + semantic timing + final state + style + needed sound, omitting irrelevant parts and honoring the model's actual capabilities and duration limits. Each supplied reference must have an explicit role (identity/product, setting, style, first/last state, motion or audio), exact project path, what to preserve and what may change. Resolve conflicting references from user priorities; ask only consequential ambiguity. Preserve recurring identity/product details, location geometry, palette and screen direction. Never invent @reference syntax, unsupported upload/audio or factual claims from a reference.
- Reuse local/supplied assets first. Generate imagery for needed missing content; generate footage when subject motion is necessary and cannot be expressed by available components/assets. Do not call a video model just to pan a still. Use images/footage as meaningful focal subjects, distinguish illustration from evidence, and retain attribution/source metadata.
- For factual/news work read sources with available search/browser tools, verify event date and media relationship, then import actual media. Save publisher/URL/date/attribution in `asset_origin`/notes. An identified article screenshot may establish provenance; its page URL is not a media file. Missing relevant footage needs truthful source material/data/labelled illustration and disclosure. Do not invent search tools, URLs, licenses or downloads. Research/import is allowed browser work; composition preview remains host-owned.
- For real-page/camera scenes capture sharp full-page texture, semantic cutouts and clean backplate where required. `assets/capture-layout.json` records viewport, pixel ratio, page height and element CSS-page `{x,y,w,h}`; overlays/destinations share those coordinates. Wait for fonts/state, freeze/anonymize personal/live data, verify dimensions and recapture only changed regions. Use the appropriate device/desktop surface; output size/pixel ratio examples are not quotas. Do not redraw a supplied interface. This is media metadata, not another storyboard/runtime.
- Before initial visual production call `media/artifact_media_review phase=plan` with exact workspace-relative entry and stable `id`, `purpose`, `kind=image|video|reuse|diagram` for all useful needs; an empty plan needs supported exemption/reason. Reuse its capability result; choose one compatible authorized model per operation. The storyboard owns story/choices, host `brief.json` owns capability/outcome/job state. Submit independent assets as one bounded batch or in parallel when supported while continuing independent scene work. Query uncertain-job status/recovery before retrying.
- Save verified results in project `assets/` and use project-relative paths. Generated copies preserve original receipts and original workspace-relative `generationPath`. Mount the real visible `img`/`video` `src` or `poster`, consistent with component variables and owning HTML path; a JS value or hidden dummy is not a mounted image. `phase=check` records every planned outcome and actual HTML-referenced `path`; generated receipts verify copied bytes. Pre-existing files are reused. Missing/pending needs require resolution; unavailable/failed/declined needs need truthful reason and delivery-scope disclosure. Verify response type/signature, format/dimensions/duration/placement; HTML/JSON is not media. Use exposed providers/credentials, never an external authenticated CLI substitute. File/receipt checks are not visual or audible evidence.

### Narration, captions and soundtrack

Use `ipollowork-video-voiceover` and injected voice contract only when authorized and enabled, or explicitly requested. Preserve saved `enabled: false`; use selected valid voice or the supplied default, never hardcode provider/model/voice, request chat keys or substitute a generic TTS tool. Without narration keep composing, preserve existing audio, use truthful `estimated-reading`/silent driver and disclose partial delivery when required speech is missing; do not invent spoken assets or a pending-model placeholder, redirect to Media Studio or block file work.

Plan natural phrasing, pronunciation of names/abbreviations/numbers, emphasis and purposeful pauses in frame notes. Keep stage directions and pause markers out of voiceover spoken text. Use only supported delivery controls; do not invent pauseSeconds or SSML support or override pinned voices. A visual hold is not an inserted audio pause. Exact unsupported silence must be disclosed. Mark the complete visible scene transcript with `data-ipw-narration-source="true"`; combined marked text must exactly equal synthesis `text` and `sceneText`. Other factual titles/labels may remain without duplicating narration. Derive speech from actual scene anchors, with useful source-supported depth rather than generic filler. Keep title/takeaway, evidence labels and phrase captions distinct. Returned `wordTimings` and `wordTimingAlignment` are authoritative; save `captionElementsHtml` with its actual phrase boundaries when captions are required. After synthesis preserve `.timings.json` and replace estimates with actual returned duration/real provider word timings; without alignment use honest sentence-level captions, never character-proportional or evenly divided word timestamps. Recheck transcript and dependent beats/captions after edits; do not speed speech or omit facts to match samples. Pass `targetDurationSeconds` only for a user duration request. Reuse the storyboard estimate before synthesis; calculate once only if absent or spoken text changed, and validate requested duration against the complete final timeline rather than small batches. Per-frame explicit voice/model overrides batch defaults; auto resolves a compatible explicit voice from role/language/content, empty inherits project settings. Only use supported delivery controls explicitly saved/requested; default-path instruction stays empty.

For a narrated recipe pass its real `narration={timingSourcePath:"video/<exact-project-id>/assets/<scene>.timings.json",text:"<exact complete narration>",bindings:{"<declared event ID>":{phrase:"<exact spoken phrase>",occurrence:1}}}` to `video_component_install` instances. Use an actual provider-aligned timing file, bind every active event, and specify occurrence only to disambiguate repeated phrases; missing/ambiguous alignment needs correction or truthful disclosure, not guessed timestamps. Preserve returned literal `data-ipw-narration-binding` on the mounted host so delivery validates the same measured source/text/event map. `wordTimings` drive word emphasis/callouts/captions; no evenly split duration proxies.

Use `speech_synthesize_workspace_batch` in sequential batches of at most THREE scenes. Keep immutable per-scene output paths, returned `durationSeconds`, `timelinePatch`, `audioElementHtml` and timing data unchanged. Save each batch; carry `totalShiftSeconds` into later `sceneStart` values. After interruption retry the SAME paths so matching receipts reuse audio without another provider request. Keep existing narration until the full batch succeeds. In one entry edit insert returned `audioElementHtml` unchanged, including `data-ipw-voice*`, directly under the root. Use exactly one timeline-owned `audio[data-ipw-voiceover="true"]` per narrated scene; remove obsolete narration/manual playback/references only, preserve music/SFX. Returned items are already in visual order with cumulative shifts; never apply a shift twice or call per-scene synthesis. Keep spoken text visible through returned `timing.endSeconds`. Recovery never invents a revision, deletes successful files or requests paid media before repairing wrong-workspace/missing-project errors. Synthesis alone is not replacement success: patch actual source/audio/timing/captions before replying. Extend longer scenes and shift every dependent scene/transition/caption/audio/animation. Do not use raw TTS URLs, shell downloads, WAV-header arithmetic or invented timing attributes. Reuse approved storyboard rather than reconstructing it after assembly.

Requested captions are timed visible `.clip[data-ipw-caption="true"]` covering speech; carry `requirements.captions: true` to the supplied gate. Default bottom-safe transparent overlays use `data-ipw-caption-style="transparent-bottom"` and inline `position:absolute;inset:auto 5% 5%;height:auto;display:flex;align-items:flex-end;justify-content:center;overflow:visible;background:transparent;pointer-events:none` so global `.clip {inset:0}` cannot stretch them. Put one/two readable lines in a stable leaf `data-ipw-caption-text="true"` with id/data-hf-id, inline max-width, transparent background, centered visible text and shadow/stroke. No pill/card/band/backdrop unless requested. Caption lifecycle is framework-owned; animate that real leaf using ordinary discovered text presets and `mutate_motion`, not a reduced caption-only implementation. Custom finite seek-safe GSAP is only for unsupported semantic effects.

A finished video needs an explicit full-video music decision before assembly. Product intros/explainers/promotions default to a suitable instrumental bed; speech is not a reason to omit it. Save `music_prompt` (mood, energy/pacing, instrumentation, vocals/no vocals, coverage, speech relationship). Exactly `music_prompt: none` is valid only for user-requested silence or approved original-sound-only intent, with reason in notes; never overwrite required music/failed sourcing with AI silence. Script-only assets may remain pending; finished sound may not.

Reuse supplied/local tracks first, otherwise discover actual authorized music/SFX sourcing or generation. TTS authorization/timeline support is not a music generator. Compare a bounded suitable shortlist, record title/source/license and concrete fit, save actual `music_asset` and mount that same file. Listen/inspect when supported, without inventing an audition. Missing suitable licensed/authorized decodable audio is partial delivery. Preserve pinned music/effects during speech edits. Bed uses `data-timeline-role="music"` and `data-ipw-bgm="true"`; effects use `data-timeline-role="sfx"`. Use separate framework-owned editable clips with explicit source/start/duration/track/volume, matching trim/source length and real coverage. No assumed looping or stretching a short effect across the film.

Choose scene timing from measured speech, measured music cues, source footage or silent reading. Set restrained supported levels/fades/ducking, audition intelligibility and verify trim/loop coverage. Plan sound early; place final effects against locked visual events and retime them after edits, not every word/cut. Music-led cues use actual analysis; a quiet narration bed needs no beat detector. Missing/muted/wrong-path requested BGM/SFX fails its audio requirement; explicit disabled/unavailable sound is disclosed.

- Keep static `data-composition-variables` aligned with manifest IDs; preserve editable nodes/labels/connectors/data, brand assets, theme inheritance and selection hooks. Readability/overflow/overlap repairs retain native editable meaning. Framework owns playback/audio sequencing; never mute or replace tracks to conceal a preview defect.

## Host export and publication

The runtime contract decides render ownership. If the app supplies a host-managed export key, save the source and stop for its validation/render continuation; do not call render start/status or create a second export. Continue only its supplied idempotent browser job and verified MP4 path. Otherwise for requested MP4/export or publication call `ipollowork_extension_call`, `extensionId=media`, `action=video_render_start`, `args={sourcePath:"video/<exact-project-id>/index.html",operationKey:"<stable-export-key>"}`, then `video_render_status` with the same args at returned intervals until complete/failed. Host starts bundled Studio; no guessed versions, CLI installs, manual Export, endpoint exploration, delegated probe agent or schedule/calendar for immediate publishing. Actions remain discoverable outside video-typed chats. Preparing/rendering is progress, not completion; use completed `outputPath`, or report exact failure.

Export-only does not authorize publication; edit-only does not authorize export. Reuse the original explicit publish authorization and exact draft/job/key on continuation; never resubmit an uncertain publication.
