# iPolloWork Website Layout Catalog · core-v1

Start with `../core-v1-index.md` for shared relationships and routing, then the website rules. This catalog indexes flowing webpage sections. Read `layout.md` for fit, slots, variants and provenance, and `shared-contract.md` before copying.

| File | Type | Relationship | Fits | Slots | Trial capacity | Variants | Verification |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `hero.html` | site | statement-visual | Product, service or campaign promise | Eyebrow, title, body, actions, visual | One promise and visual | Adjust proportions; stack at narrow widths | Source/materialization only |
| `feature-grid.html` | site | parallel | Peer capabilities or benefits | Title, feature headings and bodies | 3–6 short items | Change columns and grow vertically | Source/materialization only |
| `step-sequence.html` | site | sequence | Onboarding or process | Title, ordered step headings and descriptions | 3–5 steps | Horizontal to vertical flow | Source/materialization only |
| `evidence-pair.html` | site | attributed-evidence | Sourced observations or case voices | Title, quotes, attributions | Two sourced items | Stack or remove unused evidence | Source/materialization only |
| `plan-comparison.html` | site | comparison | Options on shared criteria | Title, plan names, details, features, actions | 2–4 options | Rebalance columns; stack with labels | Source/materialization only |
| `focused-cta.html` | site | action | One next step after context | Title, explanation, action | One focused action | Align inline or stack | Source/materialization only |

Responsive behavior, keyboard interaction and real-model selection still require rendered/client acceptance. These sections grow with content; never apply a PPT fixed-height or shrink-to-fit rule. Counts describe examples, not required sections or content limits.
