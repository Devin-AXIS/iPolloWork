# HyperFrames Video Rules

Use for `video`, including template application, custom generation and targeted edits. The active session's exact project, runtime, media actions and editor contract are authoritative. In the [shared guidelines](shared-guidelines.md), consult only sections 2–3 for scope/content, section 5 for layout selection, and section 7 for media. Read [video-motion-principles.md](video-motion-principles.md) once for initial generation or substantial scene redesign. Read [video-acceptance.md](video-acceptance.md) once before final validation; targeted edits run only its affected checks plus core playback. Do not load unrelated category guidance.

## Plan content and reuse

Read the brief, current `index.html`, template guide, tokens and existing assets. For initial/full generation, plan audience/message, narrative shots and visual beats, required media, actual assets, then timed HTML composition. Use a compact storyboard giving every scene a purpose, visible content, narration intent, media need and approximate duration. For every substantive scene, include the compact narration beat map defined in `video-motion-principles.md`; it binds each spoken intent to a time range, visual focus, visual action, and result or hold. A finished-video request proceeds through that plan to the actual composition and narration without an extra review gate; export only when requested. Pause for script review only when requested or a consequential unresolved decision requires the user. A script-only request saves the script without generating media or changing the composition. Never repeat an already supplied confirmation. Content determines scene count and timing; sample counts and durations are not quotas. An explicit user maximum remains strict. For targeted edits, preserve unrelated scenes, media and user changes.

Use the existing Studio `STORYBOARD.md` as the durable script and shot plan, not a new JSON format or an additional planning document. Write the narrative first (message, audience, hook, development and payoff), then break it into shots. `theme: "ai-auto"` derives a creative direction from the brief while preserving current Work design tokens; a manually selected Work theme ID applies that design system. `visual_style` stores overall natural-language direction. `music_prompt` describes the full-video music direction; when empty, infer it from content and pacing. `music_asset` pins the actual project-relative audio file after sourcing, so a direction cannot be mistaken for a complete soundtrack.

Use native `## Frame N — Title` sections with `scene`, `duration`, `transition_in`, `status: outline`, `voiceover` (the spoken line), and optional `speaker` only when dialogue or character identity matters. Ordinary narration does not require a character name. Optional `voice_id`, `voice_model`, and `voice_name` select a library voice for that shot; `voice_id: auto` delegates a suitable authorized choice, while empty fields inherit the project default. Put per-shot production choices in metadata: `camera`, `asset_source` (`auto` delegates the decision; otherwise `existing`, `search`, or `generate`; `code` for editable graphics requiring no imported visual), `asset_kind` (`image` or `video`, omitted for AI choice), `asset_brief`, `asset_origin` (source URL/attribution or generated-illustration description), `asset_reference` (exact local project media path), `sound_effects` (event/time) and `sound_effect_reference` (exact local project audio path). Keep research URLs in `asset_origin`, not in a local asset slot. Use `music` only for a deliberate per-shot override. Keep extended source notes, composition treatment and the beat map in the narrative body. Decide the picture first and then how to obtain it; a planned source is not a completed asset.

The Studio script table edits this same file. Read its latest saved content before generation/apply; respect pinned visuals, music, effects and voices. Saving or reordering rows alone does not rebuild or retime the video. During generation/apply, synchronize composition and audio, matching existing frames by `src` rather than old row numbers. Add `src` only for a real built sub-composition; do not invent frame files or use the entire root video as every frame's source. Advance `outline` to `built` to `animated` only after the corresponding implementation exists. Inline voiceover is enough for short pieces; reuse `SCRIPT.md` when one exists or longer narration needs it. Do not maintain two independently edited transcripts. Update only affected frames after edits and replace estimated shot timing with measured narration/media timing before final assembly.

For a finished video, resolve the full-video music decision before assembly, even when the user leaves it to AI. Product introductions, explainers and promotional videos need a suitable instrumental music bed by default; narration is not a reason to omit it. Save a content-led `music_prompt` (mood, energy/pacing, instrumentation, vocals/no vocals, coverage and relationship to narration). Use exactly `music_prompt: none` only when the user requests no music or the approved script intentionally uses original sound only; explain why separately in notes. Never override a required soundtrack with an AI silence decision. Do not change a failed sourcing attempt to none to pass validation. A script-only request may leave assets pending; a finished soundtrack may not. Discover actual capabilities: speech synthesis is not music generation. Without a configured music generator, source a suitable licensed track and record its provenance; if neither route succeeds, report partial delivery, not completion.

Choose a suitable authorized track, not merely the first downloadable file. Compare a bounded shortlist against the direction, record title/source/license and a concrete fit rationale in script notes, then save its actual project-relative `music_asset` and mount that same file. Inspect/listen when supported; do not claim an audition that did not happen. Verify trim/loop coverage, supported fades and intelligibility beneath narration. If no suitable source is available, report partial delivery with the missing asset rather than pretending a planned soundtrack is complete.

Subject/fact corrections must propagate through affected script lines, actual spoken audio, rendered text, imagery and captions. Regenerate changed narration and retime affected clips; preserve unrelated user edits. Replacing a wrong picture with a logo while retaining obsolete narration is not a completed correction. A favicon is branding, not a substitute for requested product screenshots or explanatory material.

For each shot, settle these choices before media generation:

| Decision | Record in the existing frame narrative                                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Content  | What the audience learns, exact narration or silent reading order, and the final visible state                                                       |
| Asset    | Reuse supplied/local media; search/import factual images or footage; build editable graphics; or generate a missing image/video, with a content-specific reason |
| Framing  | Focal subject, overview/detail endpoints and a motivated camera move or deliberate locked shot                                                       |
| Motion   | Existing component/preset, meaningful beat events, and incoming transition intent                                                                    |
| Sound    | Narration or explicit silence; music mood/energy and its coverage; SFX tied to named visual events, or a reason no effect is needed                  |

Static product/editor screenshots, typography, data and diagrams often need only editable components and framing. Generate an image when missing visual content helps explain the subject; generate footage when motion in the subject is necessary and cannot be expressed by the existing asset/component. Do not call a video model merely to pan across a still. Preserve source evidence and label illustrative imagery. These choices feed the existing `artifact_media_review` plan in `brief.json`; the storyboard explains the story, while that host-owned record owns capability and asset outcomes. Do not duplicate generation-job state in the storyboard.

For news or factual reporting, use available search/browser tools to read the source article, verify the event date and the relationship of each image/video to the subject, then import the actual media. Keep publisher, source URL, date and attribution in `asset_origin` or frame notes. An article screenshot may establish the source when clearly identified; the article page URL itself is not an image/video file. Never present unrelated stock media or generated illustrations as footage of a real event. If suitable footage is unavailable, state the gap and choose a truthful treatment such as attributed source material, supported data or a clearly identified illustration. Research and media acquisition are allowed browser work; the host owns composition preview. Do not invent search capabilities, media URLs, licenses or successful downloads.

Read `core-v1-index.md`, `core-v1-video/catalog.md`, and `core-v1-video/motion/catalog.md` metadata once. Select the primary temporal pattern from the scene's narrative verb, then consult `core-v1-video/motion/component-map.md` for matching Video Studio components and secondary capability overlays. A component's default primary mapping does not prevent using it with another listed pattern when that pattern's recipe and acceptance conditions are implemented. Shortlist at most three scene bodies and three mapped components; open only selected sources and relevant guidance. For every substantive scene, record `scene → narrative job → motion pattern → component ID`, or a specific reason no listed component fits. Install the selected IDs in one call to `media/video_component_install` with the exact `video/<project-id>/index.html`; use the returned host-timed `data-composition-src` snippets, stable scene IDs, unique `data-composition-id` values, real `data-variable-values`, `data-ipw-registry-component`, `data-motion-pattern`, `data-ipw-timing-source`, and executable `data-ipw-beats`. Do not redraw, paraphrase, or imitate a mapped component after selecting it. A custom scene must declare `data-ipw-component-decision="custom:<specific structural reason>"`; visual preference alone is not a sufficient reason. Read `shared-contract.md` once before implementation, not once per scene. Reuse fitting spatial and temporal references or write a new composition in the active visual language only when none fits. If references or the install action are absent in an older session, inspect actual local files and record the missing capability instead of inventing paths or pretending a component was reused.

Video layouts describe spatial content slots, not complete compositions, timelines, narration or required scene duration. Give each substantive scene a temporal story pattern and observable Establish, Develop, and Land states under the motion principles. Never import PPT page roots or website responsive behavior into a video scene.

Make the middle of the scene visibly develop: explore the imagery, connect subjects, advance a route, accumulate evidence, compare values or transform a state in narration order. Match scale, framing, crop and pace to those changes. Avoid repeating the same entrance or camera treatment in every shot, and do not leave a static card unchanged through a long explanation. Transitions connect developed scenes; decorative loops do not replace development. A purposeful readable hold remains valid.

## Composition and timing

- Keep one authoritative root composition, its identity, declared stage dimensions and registered timeline. Use unique scene/clip IDs and supported editor hooks.
- Mark every full `.scene.clip` with `data-ipw-scene`. Its beat map uses scene-relative seconds, covers the complete scene without gaps or overlaps, and ends at the declared duration. Every beat binds stable `targets` to an executable `component:`, `preset:`, `custom:`, or explicit `hold:` animation reference. Keep full scene windows contiguous.
- Every scene after the first declares one incoming transition, duration, and narrative intent. Use a direct `cut` or an actual supported preset applied through `mutate_motion`; keep the returned `data-ipw-animation-reference`. Run the transition inside the incoming scene rather than overlapping full scene windows or fading the outgoing scene to empty.
- Keep mounted registry components host-timed. Preserve `data-ipw-timing-owner="host"` on the returned snippet, set the parent host to the actual scene duration, and let a completed component hold its Land state until that host ends. Never restore clip timing on the installed component root.
- Never delete or truncate the active `index.html` or `design-tokens.css` before its replacement is complete. Update in one operation, or prepare a sibling file and atomically rename it over the destination. A failed or interrupted edit must leave the last valid entry in place.
- When adding, removing, reordering or retiming scenes, synchronize the root duration, scene windows, clips, transitions, captions, audio and animation timestamps. Preserve these values for theme-only or unrelated edits.
- Use the session's FPS and quantize authored boundaries to integer frames. Serialize seconds with only the precision needed to represent `frame / fps`; do not accumulate independently rounded decimal durations. Sample reading time is planning input, never a replacement for measured audio.
- Drive movement through the existing paused, registered GSAP/HyperFrames timeline. Ensure direct seeking and replay are deterministic; no ambient CSS loops, wall-clock timers, random values or independently running timelines.
- Camera choreography belongs to the existing animation library and mapped scene components, not another runtime. For a camera-journey, read its mapped recipe once. Record `camera: component:spatial-camera-suite#<shotStyle>` for `graze-face-tour`, `depth-layer-moves`, `spotlight-hero-card`, `runway-ground-skim`, or `steep-tilt-glide`; install `spatial-camera-suite` and set its real `shotStyle` to that exact ID. Its single seekable timeline owns the camera and depth planes. Otherwise choose the native screenshot/device camera component or query shared `camera.*` presets, record at most one in `camera` with an optional note, and apply it to the actual camera wrapper through `mutate_motion`. Never infer reuse from a name in the beat map alone. Keep screen-fixed captions outside the camera transform and do not add a wrapper camera to a component that already owns its camera.
- For music-led `audio-reactive` scenes, mount the real local audio first and call `media/video_audio_analyze` once for the project entry. Select only meaningful returned onsets or sections, store them as literal scene-relative JSON in `data-ipw-audio-cues`, and bind every saved cue to an active beat motion window. Never infer cue timestamps from duration, filenames, or waveform graphics.
- Scope animation selectors to the actual scene instance. Fit entrance, readable hold and exit inside the scene window; incoming transition intervals must not obscure required information.
- Keep playback and audio sequencing framework-owned. Do not mute tracks or replace narration/music merely to avoid a preview problem.

## Visuals, assets and narration

The template owns typography, palette, graphic language and motion style. Apply theme tokens to scene styling; keep timing/tracks outside `design-tokens.css`. Compose for the declared stage and aspect ratio; change geometry intentionally for a different target, never through viewport-dependent reflow.

Follow shared asset/model rules and the active image/video generation Skills. Before initial visual production, call `media/artifact_media_review phase=plan` with the exact workspace-relative `video/<project-id>/index.html` and all useful visual needs (stable `id`, `purpose`, `kind=image|video|reuse|diagram`); an empty plan requires a supported exemption and reason. Reuse the existing plan and its capability result, and resolve one compatible authorized model per media operation. Reuse available files first. Submit independent assets as one bounded batch or in parallel when supported rather than serially blocking scene authoring. Copy completed generated workspace artifacts into this project's `assets/`, keep original generator receipts, and record exact project-relative paths in the script and HTML. For asynchronous generation, query status/recovery before retrying; never duplicate a submission whose state is merely uncertain.

Mount selected media on the actual visible `img`/`video` `src` or `poster`, resolving paths from the owning HTML file and keeping them consistent with the project asset and component variables. A JavaScript `imageUrl` value alone is not mounted imagery. Never add hidden dummy media to satisfy the check; the client validates the actual composition. Call `phase=check` after placement with an outcome for every planned ID. Generated/reused `path` is the actual project-relative file referenced by HTML; generated copies also supply the original workspace-relative `generationPath` returned by the generator so the receipt and copied bytes can be verified. Mark pre-existing assets as reused. Missing/pending outcomes require resolution; unavailable/failed outcomes require an accurate reason and partial-delivery disclosure. This media check verifies files, references and receipts, not composition quality or audible playback. Use the existing host media and search/import capabilities; do not install or authenticate an external media CLI as a substitute. Verify downloaded response types and local file signatures; an HTML/JSON response is never a valid media asset.

Follow `ipollowork-video-voiceover` and the injected voiceover contract for enablement, authorized/default voices and validation. Preserve an explicit disabled choice. Without authorized narration, continue visual work, set affected scenes to `data-ipw-timing-source="estimated-reading"` or the actual silent timing source, and report that the result is silent. Do not redirect the user to Media Studio, block file generation, leave a pending-model placeholder, or invent audio files. When narration exists, use actual returned duration, set `data-ipw-timing-source="voiceover"`, and shift dependent beats, captions and transitions together; do not accelerate speech or omit facts to force sample timing.

Plan music and SFX with the script, not as decorations after export. Reuse suitable supplied/local audio first; discover an available authorized audio retrieval/generation action only for missing assets. Timeline support and TTS authorization do not imply a music/SFX generator exists. When no suitable source is available, report that gap instead of inventing an action or file. Save licensed/authorized decodable assets locally. Use the exact `music_asset` for the music bed and each `sound_effect_reference` at its `sound_effects` cue; preserve pinned tracks during narration replacement. Use `data-timeline-role="music"` (and the existing `data-ipw-bgm="true"` marker) for the bed, and `data-timeline-role="sfx"` for effects. Both use framework-owned audio clips with explicit source, start, duration, track and volume. Keep them separately editable from narration. Source duration/trim and clip windows must agree; do not stretch a short effect to the entire film or assume an unconfigured loop.

Choose a timing driver per scene: measured speech, measured music cues, source footage or silent reading. Narrated scenes prioritize intelligibility; start with restrained music/effect levels, use the supported audio automation for fades/ducking when needed, and audition the mix. Place an effect at the action it explains (a reveal, impact, transition or interface response), not on every word or every cut. Music-led work may use measured beat cues; a quiet narration bed does not require beat detection. If sound is unavailable or explicitly disabled, record that choice and deliver only the supported scope. Missing requested BGM/SFX remains a failed audio requirement, not a completed soundtrack.

## Editability and acceptance

Keep `data-composition-variables` literal, statically parseable and aligned with stable manifest IDs; preserve fixed-brand assets and editor hooks. Save the complete composition once and let the client run its aggregate component, project, and voiceover validation. Treat `valid=false`, a missing installed source, a missing motion pattern, or an unrecorded custom decision as a failed delivery during that client-owned gate. Follow `video-acceptance.md` as the single owner of visual, temporal, playback, audio, and export verdicts; do not start a second validator or preview loop from the model turn.
