# 建表预设

项目内「新建表」可以选择通用、用户、商品、订单。四种入口复用现有表格、字段、记录和双向关联；定义集中在 `src/core/table-presets.ts`，不新增依赖或系统存储表。它们是可编辑的数据结构预设，目前不提供登录认证、自动计价、支付回调、状态流转或额外的业务字段锁定，也不是新的外部插件包格式。

- `general`：名称。
- `users`：名称、头像（已有图片 URL）、手机号、邮箱、状态。
- `products`：名称、封面、类型、售价、币种、状态。类型覆盖课程、实物、游戏道具和服务。
- `orders`：单商品订单；订单直接关联一个购买用户和一个商品，反向为多条订单。数量、成交单价和应付金额在订单表内，不自动创建明细表。

订单的 `bindings.users` / `bindings.products` 可指向**当前项目**已有表的稳定 ID 和当前结构版本，兼容自定义命名；不按名称猜测绑定。未指定的表会新建。已绑定的表保留原字段与记录，只增加反向关联字段。版本过期或字段名称冲突时整笔创建回滚；重新读取结构后解决冲突。数量、成交单价和应付金额是独立普通字段，当前由调用方填入，不自动复制商品价格或计算合计。既有多商品订单及其明细保留，不能将它们直接压成单商品记录。

## UI、API、MCP 共用操作

项目级 MCP 与 OpenAPI 自动暴露下面三个操作。表级连接不能创建其他表。

| 操作                   | 作用                                                       |
| ---------------------- | ---------------------------------------------------------- |
| `table_presets`        | 列举预设、字段和关联规则；可传 `locale: "zh-CN"` 或 `"en"` |
| `table_preset_preview` | 检查完整建表计划，不保存；临时 ID 不可写入                 |
| `table_preset_apply`   | 原子创建，返回真实表/字段 ID、结构及导航地址               |

HTTP 入口：`POST /api/projects/{projectId}/operations/{operation}`，请求头为 `Content-Type: application/json`。例如创建用户表的请求体（先 preview，再以相同参数 apply）：

```json
{
  "requestId": "6d8e68aa-14c4-4be8-a2d1-b7b0209c1a24",
  "preset": "users",
  "name": "会员",
  "locale": "zh-CN"
}
```

订单可追加 `bindings: { users: { tableId, version }, products: { tableId, version } }`。这些 ID/版本必须从当前项目 `data_context` 读取。名称、图标、可选描述可覆盖预设；`locale` 只控制新创建的名称与选项，不翻译已有数据。接口只接受声明的参数，非订单预设不能传绑定。

相同 `requestId` 和相同参数的重试返回原结果，不重复建表；不同内容必须使用新 UUID。AI 按需添加字段、持续写入记录，沿用 `field_create`、`record_create`、`records_import` 等现有操作。携带当前绑定的 `workbench` 后，成功创建会通过现有实时事件定位到主表；预览不导航，失败不刷新数据，其他对话不跳转。

未来的业务动作可以在这些结构上单独扩展。当前没有订单执行服务，因此这些预设不会将某张普通表变成不可修改的特殊存储，也不会自动接管现有业务数据。

## 本次验证

### 字段编辑与删除

点击列名即可编辑字段，表内和文档引用表复用同一对话框。邮箱、手机号、商品类型、状态、金额等均为普通字段，可改名或删除；选项和必填可修改。`required` 只约束记录输入，不代表字段不可删除。记录名称字段可改名，但用于记录标识、搜索和关联，因此保留文本类型且不可删除。

`field_update`、`field_delete_preview`、`field_delete` 同时通过项目/表 API 和 MCP 提供；命令接口提供相应的点分操作名。REST 支持 `PATCH /api/tables/{tableId}/fields/{fieldId}`、`GET .../delete-preview` 和 `DELETE ...`。更新传 `tableVersion`，删除传预览返回的 `tableVersion`、关联时的 `relatedTableVersion`。结构变化返回 409，不能盲目重试。

删除前检查 API 参数、已保存视图（包括关联筛选）、文档嵌入条件和启用的自动化。先调整引用，才能删字段。关联字段删除会原子清理两端字段、连线和关系索引，保留所有记录。删除普通字段会删除该列及其值，清理 API 状态和详情排序；其他字段保留。前端需确认影响范围，不主动批量删除预设字段。

普通字段支持保留原值的兼容类型调整；跨存储类型仅允许空列转换。不兼容的值、删除仍在使用的选项或将空值列改成必填均会回滚。API 和关联字段保留其类别，可改名；API 另可修改来源设置。字段管理只复用现有存储、字段注册器与元数据锁，无额外数据库表或依赖。

字段管理追加验收：35 项相关测试通过（字段、文档、查询、详情、预设、实时事件、中英文），包含真实 MCP 客户端。浏览器在专用测试库完成邮箱重命名及删除、类型选项添加、375px 名称字段保护检查；删除后手机号、其他字段及记录保留。临时测试项目已清理，当前 5710 开发页及 5711 服务已加载新版本；用户体验项目的字段与记录未修改。
