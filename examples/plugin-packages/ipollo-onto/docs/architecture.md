# 架构与扩展

## 独立产品与 iPolloWork 的边界

本项目拥有自己的界面、数据服务、数据库和扩展契约，可独立启动。iPolloWork 插件仅负责启动或连接这套服务、承载界面、传递上下文和暴露受控数据操作；不把业务代码复制进宿主，不要求独立模式安装或登录 iPolloWork。

AI 能力统一由 iPolloWork 提供，包括对话、模型选择、业务理解、建表规划、AI 字段生成和智能自动化。数据项目负责校验和执行数据操作；不接入模型 SDK，不保存模型密钥，不维护另一套 Agent 或对话历史。

独立运行时，人工操作与非 AI 自动化应完整可用。涉及 AI 的动作需要已连接的 iPolloWork；未连接时明确显示不可用或等待连接，不静默回退到其他模型。项目和单表 MCP 已实现，可由 iPolloWork 原生 MCP 配置连接；尚未实现宿主自动安装、界面嵌入和选择上下文推送。数据服务没有模型调用。

当前 MCP 调用路径：用户在任一入口提出需求 → iPolloWork AI 读取授权范围内的结构和数据 → 通过插件适配器调用本项目 API → 内核校验并保存 → 同一界面展示结果。AI 调用接受与人工相同的数据约束和并发冲突处理。

## 前端复用边界

`theme.css` 集中管理颜色和圆角，默认对齐 iPolloWork 深墨色与浅灰工作台，接受宿主提供的 `--dls-*` 变量。跨 iframe 的主题仍需适配层传递，当前没有假设 CSS 变量能自动跨窗口继承。

右上角的外观与语言入口共用轻量偏好层。外观支持浅色、深色及跟随系统，同时更新 Radix 组件、页面语义色和原生控件；首次绘制前读取保存的外观，运行时监听系统主题变化。语言支持 `zh-CN` / `en`，默认跟随浏览器语言，界面组件与内置视图订阅同一语言状态。偏好仅存浏览器，不增加数据库表。`locales/en.json` 维护英文文案与参数模板，业务名称和记录值保持原样，未知插件文案保留原文。

基础按钮、输入框、弹窗、菜单、选择器和页签直接复用 Radix；共享的标题、搜索、加载、错误和表单容器位于 `components/primitives.tsx`。不为每个按钮再造一层无差别包装。

`components/icons.tsx` 复用现有 Radix Icons，集中提供 `EntityIcon`、`IconPicker` 与 `FieldTypeIcon`；不增加图标依赖。`components/use-reorder.ts` 是表列表和字段列共用的指针排序控制，支持鼠标、触控、边缘滚动、取消及 Alt + 方向键。仅拖拽手柄捕获指针，不抢占导航或字段配置操作。

`components/resize-handle.tsx` 为侧栏和表格共用的宽度调整控件，支持指针捕获、实时预览、Escape 撤销、双击恢复默认及左右方向键。侧栏限定 200–400px，数据列限定 100–800px；移动端侧栏仍使用独立抽屉布局。宽度是当前浏览器的展示偏好，列宽按表 ID 分组、按字段 ID 保存，切换表或重排字段不会串用；不增加数据库表或写入请求。表格复用 TanStack 的列宽状态和原生 `colgroup` 对齐表头与记录。

排序与图标归属于已有项目、表和字段元数据，删除对象时一并删除，无新增业务数据表。`migrations/presentation.ts` 在默认库和独立项目库执行幂等迁移，首次按旧顺序回填表位置及唯一标题字段标记。`isPrimary` 是记录标题的身份，`position` 仅表示展示顺序；搜索、关联标签、关系图和卡片不再依赖第一列的位置。字段排序用表版本号检测冲突，表排序校验完整 ID 集合与原顺序；事务锁住所属对象，拒绝跨表、跨项目或过期列表。

项目页面、导航和表格工作台独立组合这些组件；`fields/input.tsx` 与 `fields/value.tsx` 统一字段编辑和显示。`App.tsx` 保留状态与操作协调，插件不复制数据请求或保存逻辑。

`view-registry.ts` 只定义视图契约和注册表，内置视图在 `bootstrap.ts` 载入，独立包按需载入；页签图标与名称从视图注册生成，扩展列表由统一清单及服务端启停状态生成。新增视图不用在工作台或扩展列表中添加名称判断。字段与视图包可从扩展面板导入本地 ZIP 并即时启用，支持持久化安装状态、启停与版本匹配；不下载远程代码，不宣称同进程沙箱。

## 产品层级

部署实例 → 项目 → 表 → 字段 / 记录 / 视图。初次进入直接创建项目。未来公司与集团可以作为可选项目分组，既不要求每个客户使用，也不将分组标签当作权限隔离。

子表分为导航目录、父子记录和明细表三种；后两者应复用稳定记录 ID 和关联服务，不将需要被关联的明细藏进不可寻址的 JSON 数组。JSON 仍适合可变的附加属性。

## 存储与关系

元数据位于 `iw_data` schema。每张业务表是独立物理 SQL 表，字段使用 text、numeric、boolean、date、jsonb 等原生类型；用户给出的表名不直接拼进 SQL。元数据定义保留全局 UUID，表改名不会改变引用身份。

`relation_defs` 定义源表、目标表与两端数量约束。两个关联字段指向相同定义并声明方向；`links` 只存 `(relation_id, source_id, target_id)` 一份边，反向查询读取同一行。

保存服务按固定顺序锁定关系和相关记录，校验目标表、版本和字段值，写入记录与关系差异，再更新受影响记录的版本并追加操作事件。所有步骤使用传入的同一事务连接；没有事务中调用外部 API 的路径。任一步失败全部回滚。当前事件记录的是操作和字段 ID，尚无旧值快照与撤销能力。

本版本每表最多 100 字段、每页 50 记录、单次关联选择最多 200 记录。宽表查询分块生成 JSON，避免 PostgreSQL 函数参数上限。数字以十进制字符串传输，金额不经过 JavaScript 浮点数存储。

项目创建可选择默认数据库或独立 PostgreSQL 兼容数据库。默认库项目沿用同库跨项目关联；独立项目的项目元数据、表、记录、关系、变更和扩展状态完整保存在目标库。路由通过请求级异步上下文选择连接池，REST、机器命令、结构构建、导入及后台自动化共用它，不在保存记录时访问另一个数据库。

仅新增两类存储实体：各库的 `database_identity` 保存持久身份；默认库的 `project_databases` 保存项目与数据库的路由、加密连接、项目快照和初始化状态。项目主体在独立库，因此路由目录不伪造跨物理库外键；项目 UUID 为主键、数据库身份为唯一约束，一个独立库只绑定一个项目。项目管理支持修改名称、描述、标记色及检查连接；当前不提供已有项目的原地换库、数据搬迁或在线修改凭据。

连接测试只读取版本与当前库。创建时在指定数据库的 `iw_data` 空间初始化项目，不创建数据库本身，不自动导入既有业务表；已占用的数据空间或同一默认库会被拒绝。初始化先保存待完成路由，再在目标库以固定项目 ID 幂等创建；中断后通过待完成状态恢复，不宣称两库事务。连接池首次打开时核对数据库身份，不匹配则停止访问。删除独立项目清理其业务表和路由，保留数据库与内核元数据空间。

连接配置采用服务端 AES-256-GCM 加密，API 仅返回非敏感摘要。密钥默认保存在被忽略的 `.local/database.key`（文件权限 0600），也可使用环境变量或独立文件；备份时必须同时保存默认库路由、项目数据库和原密钥。TLS 连接验证证书与主机名，可配置自定义 CA。当前提供 PostgreSQL 和瀚高兼容连接选项；实测为 PostgreSQL 15.13，瀚高具体版本及 TLS 部署仍需对应环境验证。

项目目录聚合各库信息；独立库不可用时保留项目快照并标注连接失败，不显示为项目消失，其他默认库项目仍可使用。表 UUID 的路由先查默认库，再查已配置库，成功结果缓存在进程内；尚未为大量独立数据库优化冷查询或进行容量测试。扩展启停按数据库保存，同库项目共享状态，独立库互不影响。后台自动化逐库处理，不可用的独立库不会阻断其他库。

跨物理库直接关系在当前界面和服务端均受限。同库跨项目关系仍可事务保存；跨库关系需要明确权威关系库、异步状态与补偿流程，单独设计和验收。

## 三类扩展

| 扩展           | 当前接口                                               | 当前状态                                                           |
| -------------- | ------------------------------------------------------ | ------------------------------------------------------------------ |
| 字段类型       | `FieldType`：稳定 ID、基础存储类型、编辑器、校验和显示 | 已执行；百分比字段为示例                                           |
| 数据视图       | `ViewPlugin`：数据快照与打开/新增记录/新增字段回调     | 已执行；卡片视图为示例                                             |
| 字段取值与同步 | `FieldSource`、服务端提供者注册表 / `SyncConnector`    | API 按读取获取、缓存和最新值保存已实现；同步连接器及持久调度待实现 |

字段与视图支持可信本地原生 ESM 包，清单自动发现，浏览器按需加载。注册返回清理函数，生命周期范围按依赖装入并在停用时撤销；失败回滚自己的注册。服务端字段定义随进程加载，每次业务操作仍检查当前数据库的启用状态。字段类型被任何字段引用时，停用和移除均被拒绝；自动字段迁移尚未实现。

新增简单字段只需提供独立包和清单中的 shared 入口，使用已有基础 SQL 类型和通用输入器；无需修改服务端或前端导入。安装、包格式、升级边界见 [独立插件包 v1](plugin-packages.md)。复杂定制编辑器接口后续扩展。

新增视图时，注册组件并消费 `ViewProps`。视图中的操作通过传入回调进入统一保存入口，不维护第二份业务数据。重型关系图和 3D 视图后续按需加载，避免所有用户都承担它们的体积。

动态字段保留“值类型、来源、刷新策略、保存策略”四个维度。例如竞品股价可以是数字类型，由行情提供者解析，带观测时间与短缓存，不必作为历史记录落库。查询计划必须声明是否支持该字段的筛选、排序、汇总和历史查询；不支持时清楚返回能力限制，不能对当前页临时值假装做全表统计。

同步连接器通过统一写入服务使用来源 ID 幂等更新；自动关联应使用明确的唯一匹配键，未匹配与多重匹配进入待处理状态。模糊名称匹配不能静默建立业务关系。连接器失败不应删除上一次有效数据。

## API 字段：已实现

前端以独立的“API 实时字段”入口配置返回类型、参数、来源与保存方式，复用字段选择、输入和显示组件。服务端将 `type` 与 `source` 分开，所有视图、REST 和 AI 命令共享同一提供者执行器；不增加模型服务。

本功能新增零张表。字段拥有 `fields.source` 配置，与字段一起删除；记录拥有 `record_index.api_state` 中的来源和时间状态，与记录一起删除。选择保存时，当前值写入已有的原生类型业务列，JSONB 仅保存来源元数据。选择只读时业务值保持空，值只出现在响应和短缓存中。

外部 GET 在数据库事务外完成，响应按字段原类型校验。相同 URL 与授权合并请求，进程缓存有容量上限，网络并发最多 8，单响应最多 1 MB，一次解析预算 6.5 秒。只允许服务端明确许可的 origin，凭据名称绑定来源且不返回密钥，不跟随重定向。

保存时批量锁定本页待更新记录，核对表版本和记录版本；旧请求不能覆盖已编辑记录。源参数写入会清空依赖值和来源状态。成功保存最新值及来源时间，值发生变化时与 `field.snapshot` 事件一起提交；相同缓存结果不重复写库。失败保留已保存值并标注旧值。事件保存新值及来源，当前不提供完整历史曲线或撤销。

表格先显示普通字段和保存值，再解析 API。页面可见且无编辑表单时按间隔更新，支持手动刷新；关闭页面后的定时采集尚未实现。已有模拟来源仅保留读取兼容，不再提供执行器、新建入口或生成接口。汇率和 GitHub 使用通用 JSON 提供者；公开美股只增加固定来源和响应格式适配，复用缓存、并发、类型校验和保存路径，没有专属数据库表。

API 来源配置收在字段的添加和编辑表单中，列名和结构侧栏提供上下文入口，不另建独立配置弹窗。需要变量时才显示参数绑定，固定接口可以没有参数字段。REST 与 `field.configure` 复用更新服务。更新时锁定表并检查结构版本，来源绑定变化时将已有值与状态存入现有变更表，清空该列，递增表及记录版本；在途旧请求因此无法覆盖新来源。仅修改名称、单位或间隔保留记录值与版本。新建记录只填写变量，同类接口共用配置和请求结果。

具体配置、接口和行为边界见 [API 字段](api-fields.md)。

## 统一扩展方式：参考 DeepSeek Harness

2026-09-10 确定：字段添加与后续功能扩展统一采用“小内核、能力注册、按需组合”的方向。DeepSeek Harness 的官方架构以 Cordis 上下文承载服务、事件与可撤销的注册，通过 profile 和 bundle 组合功能。这里借鉴其扩展机制；本项目的数据契约独立维护，所有 AI 继续由 iPolloWork 提供。[DSH 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)、[扩展示例](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/extension-cookbook.md)。

以下约定包含已实现能力与后续建设方向，实际进度见本节末尾。不承诺直接兼容 DSH 插件包。

### 同一套机制，不同的能力接口

统一的是插件身份、版本、依赖、配置、状态和生命周期；每类能力保留明确的类型接口，避免把所有操作都装进无类型的通用回调。一个插件包可以贡献多种能力。

| 能力     | 注册内容                             | 用户使用入口          |
| -------- | ------------------------------------ | --------------------- |
| 字段类型 | 校验、序列化、显示、编辑器与查询能力 | 添加字段 → 选择类型   |
| 字段来源 | API 参数、取值与刷新能力             | 字段设置 → 来源与更新 |
| 视图     | 组件、配置与所需数据能力             | 添加视图 → 选择类型   |
| 同步     | 连接器、映射、游标与幂等写入         | 项目 → 数据连接       |
| 自动化   | 触发器、条件、动作                   | 项目 → 自动化         |
| 监控     | 已提交的业务事件、任务状态与指标订阅 | 扩展配置与运行状态    |

内置能力与外部扩展逐步使用相同注册接口。字段与视图选择器从当前可用能力生成，并复用搜索、配置表单、状态和错误组件；复杂编辑器可提供独立组件，沿用同一交互契约。内核仍负责稳定身份、数据约束、关联一致性、版本检查和统一写入入口，这些规则不能因插件启停被绕过。

### 三种“添加”分开处理

1. **部署中安装能力**：安装或随发行包携带一个插件，声明它能提供哪些字段、视图、来源或动作。扩展列表展示实际安装及加载状态。
2. **项目中启用与配置**：选择项目可使用的能力，设置连接与凭据引用。项目配置不是权限隔离，服务端仍须检查实际授权。
3. **表中创建使用实例**：用已启用的类型创建字段、视图或规则。每个实例有自己的稳定 ID、配置与配置版本；同一张表可以有多个同类型视图。

例如安装“行情数据”扩展后，在竞品项目配置一次连接，再给竞品表添加“当前股价”字段。字段复用数字类型，来源选择行情提供者，证券代码映射到本行字段，缓存或持久保存单独选择。增加一种来源不需要重新实现表格、记录表单和关联服务。

增加“关系图”扩展后，用户可以在客户表创建“客户与商机”和“客户与合同”两张图，各自保存筛选和布局。删除一个视图实例只删除其配置；卸载视图插件时保留实例配置并标记暂不可用。

### 最小生命周期与数据保护

插件清单应声明稳定 ID、版本、内核协议范围、依赖、贡献的能力、配置结构和执行位置。浏览器渲染与服务端执行分开加载，凭据只以服务端引用传递。首期采用随发行包或私有包安装、启动时校验加载；重型视图按需加载。公共商店和任意在线代码安装后续单独建设。

加载先检查版本、依赖与配置，再登记能力。依赖缺失或初始化失败时显示具体原因，撤销本次部分注册，不能留下可点击但不可用的入口。服务与事件通过受控上下文提供，调用数据操作时必须携带项目与操作者上下文；只暴露接口并不构成对同进程代码的安全隔离，首期仍只加载受信任代码。

后续禁用流程应先停止接收新任务，再结束或取消在途工作，释放订阅、计时器与注册。已提交的数据不随运行时清理撤销。字段类型仍被存量字段引用时，拒绝直接卸载并列出使用位置，须先完成迁移；来源停用保留已有值与来源信息，明确其数据时间与不可用状态。数据库迁移和版本回退单独处理，不能把卸载函数当成数据回滚。

监控订阅提交后的事件与任务状态；外部同步和自动化不得进入保存事务。需要可靠交付的事件使用持久化执行记录，不能只靠内存回调。AI 动作只注册对 iPolloWork 的调用适配，未连接时清楚显示等待或不可用。

### 建设顺序与验收

已实现统一插件清单与持久化状态，包含基础表格、百分比、业务字段、卡片视图、业务关系图、轻量自动化、API 字段七项扩展；其中百分比、卡片和关系图是独立本地包。扩展面板提供全部、字段、视图、数据连接器、自动化分类，使用清单中的 `categories` 展示，同一扩展可归入多个分类；分类仅组织展示，不另建数据库表或复制安装状态。`extension_state` 只保存安装版本和启用状态，本地包代码与声明独立于前端构建交付。启停与创建字段/规则使用同一元数据锁，防止刚停用又创建出依赖字段；普通记录写入不使用这把锁。服务端每次创建字段检查可用性，前端隐藏不可用字段与视图，停用当前卡片视图时回到基础表格。

新增业务字段使用通用输入与显示组件，没有复制 AINO 组件或业务模块。扩展列表支持添加、启用、停用、移除及更新至当前发行包版本；更新不会从网络下载包，也不支持数据降级迁移。当前视图仍仅切换类型，尚无每表多个视图实例的持久化配置。真实 HTTP 字段提供者与可信本地字段/视图包安装已实现；远程市场与沙箱继续后续建设。

新增字段、视图或来源的验收标准是：只新增插件实现和声明式装配项，无需修改表格工作台、记录保存或关系业务代码；依赖失败可定位、重载不重复注册、停用保留数据。扩展页只展示已实现状态，不能把未来能力列为已安装。

## AI 接口

`GET /api/capabilities` 返回命令及结构构建的 JSON Schema、扩展能力与约束。`POST /api/commands` 已有真实分派器，支持项目创建、结构预览/创建、结构读取、字段创建、记录分页查询/创建/更新、JSON 导入和自动化规则创建。人工界面和命令均调用相同服务。`GET /api/projects/:id/schema` 输出稳定 ID、字段、关系与版本。

结构构建采用严格的增量输入：一次新增最多 20 张表，每表最多 100 字段、最多 50 条关系；首字段是文本标题。可以创建新项目或在已有项目增加表，关联已有的跨项目目标表时必须提供 UUID 和结构版本。只新增，不隐式覆盖或删除同名表。引用用输入内的结构键解析为真实 UUID，返回键到 ID 的映射。

预览在事务与保存点中执行相同校验后回滚，不留下表或项目；预览的 ID 是临时的。正式执行一次提交全部 DDL 和关系定义。`requestId` 通过事务锁和已有变更表的唯一回执索引保证幂等；同请求同内容返回第一次结果，不同内容拒绝。回执随项目删除而删除，幂等保证限于项目存续期。所有修改仍受字段约束及记录版本保护。

按外部编号等文本键导入最多 200 行，来源方使用 `records.import` 或 REST 接口推送；匹配已有记录更新，未匹配则创建，多重匹配拒绝。对实际使用的匹配键建立索引，导入与同表记录写入串行；每批全部成功或回滚。此能力不等同于自动轮询外部 CRM，真实 API 字段已支持按读取获取；外部连接器仍待实现。

详细请求示例见 [AI 结构与数据接口](ai-interface.md)。关联查询可以返回访问过的表、记录和来源作为证据，不输出模型隐藏思维链。所有模型能力仍由 iPolloWork 提供，当前通过项目/单表 MCP 接入。项目范围在启用关系图扩展后提供 relation_graph，读取同一批真实记录与关联边；每次查询有节点和边数量上限。

## 轻量自动化：已实现的最小运行器

当前提供一个真实动作：记录创建后，字段为空则填入指定值；非空值保留。规则存于 `automation_rules`，配置使用字段 ID 和经过类型校验的值。每个表最多 50 条规则，前端复用字段编辑器，并显示最近执行结果、暂停和删除操作。

本地服务每 1.5 秒扫描有待处理记录创建事件的规则，每轮最多 100 条规则。每条规则推进一个持久化游标；变更、游标与运行结果在同一事务保存。进程退出后重启可以继续；重复工作器由数据库锁保护。新规则从创建时的事件末尾开始，不追补历史记录；规则或插件暂停后保留待处理事件，重新启用继续处理。用户覆盖非空值时自动化跳过它。

失败保留游标并记录原因，30 秒后重试；删除规则会取消后续处理。当前只监听创建事件，自动化写入产生更新事件，不递归触发自己。规则不调用外部网络，不持有模型密钥。自动化扩展停用后，后台扫描器保留在服务内但不执行动作；它不是任意插件热卸载的执行容器。

后续再增加触发器、条件、提供者动作与通用调度；AI 动作交给 iPolloWork。涉及外部网络时必须增加独立的持久化任务、幂等与取消语义，不能把外部请求加入数据库事务。

`tests/kernel.test.ts` 使用真实 PostgreSQL 验证：类型保存与精度、跨项目双向修改、并发一对一争用及回滚、旧版本冲突、非法关联目标、分页与转义、53 字段宽表、扩展校验及 API 输入边界。

新增测试验证丰富字段、结构预览回滚、并发请求幂等、跨项目结构版本、扩展启停保护、JSON 导入回滚、自动化暂停恢复以及机器命令发现。配置第二个测试数据库后，同时验证独立项目的真实数据位置、机器接口和 REST 路由、并发请求隔离、关联和导入、后台自动化、加密凭据重连与初始化恢复。

## 按需业务导航

`src/core/exploration.ts` 定义 AI 与界面共用的探索条件；`src/server/exploration.ts` 在既有 `relation_defs` / `links` 上进行有界逐层查询。关系端点沿用原主键和反向索引，不建图数据库或关系副本。目录与搜索也复用现有表、主字段索引及项目/单表范围。节点摘要沿用关系图的批量读取实现。

模型选择哪些业务领域和关系值得探索，数据服务负责范围检查、字段依据、去重与截断。视图使用返回的同一份图数据；查询本身不要求安装视图插件。不引入模型服务、推测关系持久化或跨物理库联邦查询。

## 对话绑定与操作跟随

独立插件按宿主 workspace/session 保存项目绑定和最后路由，只存 UUID、名称及页面偏好，不复制业务正文。`workbench.id` 是会话显示路由标识，不是身份或授权；服务仍按原项目/单表范围执行。

现有 MCP/operations 的可选 `workbench` 在输入校验后剥离，业务逻辑与事务保持原样。提交完成后，轻量活动通知附带实际目标；批量写入通过已有记录索引确定分页，文档更新附带稳定块 ID。SSE 按工作台过滤活动，同项目数据失效通知仍共享。通知不持久化、不记录推理、不保证离线重放；断线后重新读取当前数据。

界面短时合并跟随目标，用户编辑时暂停。表格刷新与文档草稿继续使用既有版本保护；恢复时只定位到最新目标。无需新依赖、数据表、消息队列或宿主 Agent 改动。企业业务上下文仍由 AI 经既有查询工具按需读取，未增加全文检索或自动记忆抽取。
