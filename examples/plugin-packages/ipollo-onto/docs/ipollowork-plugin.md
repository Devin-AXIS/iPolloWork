# iPolloWork 插件

iPollo Onto 是独立产品。插件包含 **工作台页面 + AI 工作流 Skill**，数据操作复用现有项目 / 单表 MCP。工作台直接显示同一套 Onto 前端，项目、表格、关系图和文档共用原来的数据。

## 安装和打开

1. 从 [v0.1.4 发布页](https://github.com/Devin-AXIS/iPollo-Onto/releases/tag/v0.1.4) 下载 `ipollo-onto-0.1.4.ipollowork-plugin`，或本地构建。0.1.0 是之前的纯工作流包，没有工作台页面。
2. 在 iPolloWork 的扩展页面安装或升级，启用 **iPollo Onto**。
3. 点击右侧面板的 **+ → iPollo Onto**，也可以从插件详情打开应用。无需输入网页地址。
4. 独立 Onto 服务需保持运行。工作台自动连接本机生产界面 5711 或开发界面 5710，并记住上次打开的项目 / 表。前端必须使用此版本源码，包含工作台握手；未启动时显示重试提示，不会把错误页当成连接成功。
5. AI 数据操作仍通过项目 / 单表 MCP：在 Onto 项目管理或表菜单打开「API / MCP」，复制真实地址，在 iPolloWork 原生 MCP 设置里添加，关闭 OAuth，确认连接成功。已有连接保留，不需要重建。

跨表分析使用项目连接；只处理一张表可选单表连接。模型与 AI 执行都由 iPolloWork 提供。数据库密码或 API 密钥不会进入插件包或工作台上下文。

## 页面与 AI

工作台共享当前项目 / 表的 ID，不自动发送记录正文。通过宿主的 Workspace App 工具可发现：

- `onto_status`：读取当前页面路由、连接状态、本对话绑定的项目及 `workbench`。
- `onto_bind`：将已存在的项目用于当前对话，传 `null` 解除绑定；不创建项目、不扩大 MCP 范围。
- `onto_navigate`：打开相对页面路径，例如 MCP 返回的 `navigation.href`，等待页面确认后返回。只改变导航，不写业务数据。

AI 查询、建表、导入、关联分析、更新文档仍调用同一套 Onto MCP；没有在页面里增加第二个模型或数据库接口。

0.1.4 将绑定与最后页面按宿主工作区、对话分别保存在插件自己的本机偏好中；新对话不继承旧对话项目，无对话标识时只保留临时状态。浏览其他项目不会改变绑定，可用「用于当前对话」明确切换。业务记忆继续保存在既有表和文档里，Skill 指导 AI 在任务开始时按需查询；绑定不是将全部资料塞入上下文，也不保证任意 Agent 每轮自动召回。

操作可选携带 `onto_status` 返回的 `workbench`。成功通知会包含实际表、记录页、文档和内容块位置；页面合并短时间内的定位，展示最新已提交内容。记录批次一次提交后可见，不做逐字模拟动画。同项目的其他对话仍接收数据失效通知，但不接收此对话的进度与跳转。手动编辑时暂停跟随，保留最新目标，用户点击「继续跟随 AI」恢复；原文档版本与冲突机制保留。

0.1.5 完整云端包同时升级工作台、前端和数据服务，默认使用内置 SQLite。原独立 PostgreSQL 服务的数据不会自动迁移。nto 的任务中启用：先建立或复用真实表、关系和文档，再分批写入、沿关系查证、补充结果。`records_import` 直接接收结构化记录，不需要中间文件；它保留原名称和参数，旧调用不受影响。`schema_apply` 与 `records_import` 额外返回工作台 `navigation.href`。

可见的项目页通过 `/api/projects/:id/changes` 订阅本进程内的轻量 SSE 通知。MCP / operations 成功写入后才发数据更新通知；失败不刷新成成功状态。进度浮层显示工具真实开始、完成或失败，以及本批新增/更新数，没有预计百分比或模拟打字。建表保持原有事务：提交后整批可见。通知不含记录正文、不落库，隐藏或关闭页面释放连接；重连重新读取当前数据。编辑表格、弹窗或文档时暂缓主表刷新，文档正文沿用自己的版本同步与冲突保护。

该通知用于同一 Onto 进程的 MCP / operations 调用，不是跨进程数据库变更捕获，也不监听 Agent 内部思考或其他工具。没有改动宿主、Agent、其他插件、数据库结构或模型配置；它不能让未知宿主强制遵循 Skill，也不自动获得新项目或范围外访问权限。

## 打包边界

schemaVersion 2 包含 UI、Skill、本地启动服务和完整运行制品。默认由宿主的 SQLite 运行时提供数据库能力，不包含数据库安装器、用户数据或私钥，不在用户机器上安装依赖。

源码在本目录，生产制品位于 dist/package，宿主统一负责签名、资源完整性检查、安装和更新。运行数据存放在宿主提供的插件专属持久目录；更新制品与业务数据分离。客户端要求 >=0.50.18。

构建和验证命令见 [README](../README.md)。可选独立 PostgreSQL 项目仍使用原来的请求级数据库路由、连接加密与项目 MCP 范围，不由默认 SQLite 的项目绑定扩大权限。导入 Onto 字段/视图 ZIP 与安装宿主插件是不同操作。
