# Linear Sprint Planning

1. Read the target team's active and upcoming cycle, unfinished work, priorities, dependencies, and estimates.
2. Identify blockers, unestimated items, and work that does not meet the requested scope.
3. Propose a bounded plan with a clear must-do set and explicit stretch items.
4. Do not move issues, change estimates, or assign owners until the user confirms the proposed plan.
5. After updates, re-read the cycle and report the final issue set and unresolved risks.
