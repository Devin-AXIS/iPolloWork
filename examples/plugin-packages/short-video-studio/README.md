# iPolloWork 短视频插件

独立开发目录，不属于 iPolloWork 主仓库。现已提供签名的 **0.1.0 可导入核心版**，但**尚未达到 LibTV 全量功能对等**；以下明确区分已实现、已验证和未完成范围。

## 安装与使用

在 Work「扩展 → 导入插件包」选择 `dist/short-video-studio-0.1.0.ipollowork-plugin`，然后从插件详情「在对话中使用」打开「短片工作台」。不需要修改或合入主仓库，不需要 LibTV 账号。

在左侧说：“读取短片工作台，写一个四镜头短片剧本，先规划不要生成。”也可以在右侧添加节点、上传素材、编辑剧本、角色与分镜。生成素材通过 Work 原有的图片、视频、百炼配音渠道；有授权配置不代表服务商实际接受该密钥。

分镜选择素材后点「编排到轨道」，配乐从素材库单独加音轨，最后「交到 Work 剪辑」。工程实际写为本地 HTML 和素材，不是一个混合 MP4。当前 Work 的通用插件协议没有“直接切换原生视频面板”动作，因此通过左侧对话输出文件入口，再在文件卡中选择视频工具；**没有声称已经一键自动切换**。

数据归属：`short-video/<project-id>/` 是用户的项目、素材和最近 50 个版本；`video/<id>/` 是独立原生剪辑工程。卸载会删除插件代码、Skill、私有临时上传数据，但保留这些创作文件。

## 已确定的产品边界

- 参考 LibTV 的创作流程：节点画布、脚本、分镜、角色、图片、视频、音频和素材。
- 不复制它的 Agent 聊天栏。对话只使用 iPolloWork 左侧，由 MCP 读写插件工作台。
- 工作台亮色/暗色跟随 Work，包括画布、节点、工具栏、参数、素材库和弹窗；系统偏好仅用于尚未收到宿主主题的独立预览。
- 最后交接的是**可编辑多轨工程**，不是把所有内容压成一个 MP4。视频、原声、配音、音乐、音效和字幕保持独立片段。
- 合成、裁剪、分割、变速、音量、字幕和后续保存继续用现有 Video Studio；不开发第二套剪辑器。
- 交接后，原生 `index.html` 是剪辑结果的唯一权威来源。禁止用旧分镜数据全量覆盖用户已经剪过的工程。
- 后续生成新素材应作为明确选中的新片段加入或替换，保留无关编辑。自动双向同步尚未实现，不能冒充已有能力。
- 插件代码、Skill、服务和授权由插件生命周期管理。用户交接/保存的视频工程属于用户，不应因卸载插件被删除。

## 本次已落地

- 节点画布：添加、拖动、缩放、平移、复制、连线、删除、撤销/重做与属性面板。
- 项目：创建、切换、重命名、输入暂存、自动保存、版本冲突保护、重新载入及版本快照。
- 剧本按段落拆分镜，分镜排序、时长、描述、字幕、素材绑定；角色档案及角色图节点。
- 本地图片、视频、音频的分块上传/工作区导入、预览；256 MB 单文件上限，路径/符号链接校验。
- Work 图片生成/参考图编辑、视频生成模式/首尾帧/多模态参考、CosyVoice 配音适配；界面参数来自 Work 能力状态，生成请求持久化并防重复提交。
- 标准 MCP Apps：左侧可读写同一个项目、查询渠道、导入素材、发起生成和交接；没有新增独立聊天栏。
- 原生多轨 HTML：片段 ID、起点、时长、媒体入点、速度、音量、原声、独立配乐和可编辑字幕。不覆盖交接后用户剪过的 HTML。
- 主题跟随 Work 的初始化和实时通知，包括画布、节点、属性、素材、弹窗；不改变视频内容颜色。
- 插件自带 Skill、本地服务、Workspace App 和会话入口，签名打包；没有全局手动安装的 Skill，没有引擎内部代码。

## 验证情况（2026-09-10）

- 40 项 Node 单元测试通过：轨道时间、转义、越界、版本冲突、路径隔离、分块顺序、重复交接、生成幂等和图片/配音适配。
- 2 项真实宿主兼容测试通过：原生时间信息编译/媒体提取/轨道转换，以及签名包上传校验、安装、UI 载入、服务调用和卸载。
- 1 项隔离 Work HTTP 验收通过：实际导入验证与安装接口、UI 获取、服务创建工程、临时上传、卸载后私有数据消失且用户工程仍在。不会写入用户正在使用的插件安装状态。
- 浏览器实测：新建项目、输入保存、切换视图、项目重新打开、亮/暗切换、540px 窄栏、视频实际解码（640×360 / 4 秒）、4 轨 7 片段交接落盘。
- 自动化浏览器没有成功接管嵌套沙箱的文件选择器；分块上传已通过真实服务/HTTP 测试，**文件选择器 UI 尚未通过完整自动化验收**。
- Work 真实图片渠道已发起一次低质量 1024×1024 验收请求，服务商返回“第三方服务授权已失效”。没有生成成功，也没有自动重试。当前视频渠道列表为空，因此视频生成与配音的真实付费出片未验收。
- **原生桌面剪辑器中的分割、调音、保存再打开尚未完成现场端到端验收**，不能用静态兼容测试替代。主仓库 `data-label` 工作树未变更。

开发：`pnpm install`、`pnpm build`、`pnpm dev`。验证：`pnpm test`，设置 `IPOLLOWORK_SOURCE_ROOT` 后运行 `pnpm test:host` / `pnpm test:api`。打包需通过环境变量提供已有可信发布者的 `IPOLLOWORK_PLUGIN_SIGNING_KEY` 文件路径与 `IPOLLOWORK_PLUGIN_KEY_ID`；私钥不会进入包内。

`scripts/work-dev-host.mts` 仅用于明确启用的隔离联调：使用 Bun、`SHORT_VIDEO_USE_WORK=1`、`SHORT_VIDEO_AUTH_CONFIG` 和 `IPOLLOWORK_SOURCE_ROOT`。它复用 Work 渠道实现；测试工程和记录仍写入插件开发目录。此适配器不进入发行包，不是运行依赖。

## 尚未实现的全量差异

LibTV 的云协作/分享发布、云素材授权库、完整导演台/3D 机位、逐帧拉片与重拍、全套智能混剪/批量广告流程、音乐生成、画布分组/多选/小地图及全模型覆盖，均不在当前核心版完成清单。风格和镜头下拉只是自己的提示词预设，不等同这些高级功能。

后续完整验收还需要有效图片授权和至少一个 Work 视频渠道，并在实际桌面视频工具完成分割、调音、保存、重开测试。不会为了实现这些差异，私自更改 Work 主仓库或调用 LibTV 私有接口。
