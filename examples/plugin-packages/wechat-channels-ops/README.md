# 视频号运营台

iPolloWork 插件集内置的视频号运营插件，ID `wechat-channels-ops`，版本 `0.1.7`。参考抖音运营台的创作、账号、素材与任务流程，采用视频号助手的账号浏览器执行方式。

顶部「管理账号」打开账号管理弹窗，扫码添加、重新登录、编辑资料和切换入口集中在弹窗内。扫码会打开账号专属的视频号助手登录会话；进入官方后台首页后，插件从可见昵称和「视频号ID」自动核验并保存账号。关闭按钮、Esc 或点击遮罩返回原页面，保留创作中的草稿；主导航保留创作、作品、数据、评论与记录。

## 当前可用范围

| 功能 | 独立本地页面 | 安装到宿主后的执行路径 |
| --- | --- | --- |
| 多账号资料、定位、受众、风格 | 可保存、编辑、切换；扫码入口会说明需主软件 | 账号独立浏览器扫码，登录后自动识别昵称与视频号 ID |
| 视频草稿 | 保存、编辑、版本管理、刷新恢复 | AI 会话起草与回写 |
| 视频与封面 | 上传、工作区导入、实际素材预览 | 领取任务后交给宿主上传 |
| 发布任务 | 固定内容、去重、取消、复制执行指令 | 核验账号、领取、提交前标记、实际点击、回读结果 |
| 作品与数据 | 页面、数据存储和读取结果契约 | 从视频号助手可见页面读取并回写 |
| 评论 | 评论展示和回复任务准备 | 同账号读取与指定评论回复 |
| 日程 | 执行规则已提供 | 复用宿主调度；需主软件运行且登录有效 |

**已完成本地验证、主软件目录安装、账号弹窗与扫码会话接入；当前环境没有替用户扫码，因此真实账号登录结果、视频号发布、评论、数据与日程仍需有效账号联调。** 账号识别和网页操作复用宿主浏览器的可见页面，没有嵌入未公开平台 API，也没有把本地准备或模拟测试视为线上成功。真实联调中若缺少稳定账号/作品/评论标识或页面能力，应暂停并报告。

## 本地启动

需要 Node.js >=22.22 和 pnpm。

```powershell
pnpm start
```

使用终端打印的完整地址打开页面（包含 `#token=`）。启动随机本地端口，只监听 `127.0.0.1`。页面会将启动凭证保留在当前标签页并清除地址栏片段，支持直接刷新。AI 按钮在本地模式显示可复制指令，不伪装模型输出。

默认数据保存在 `~/.ipollowork/plugin-data/wechat-channels-ops`。环境变量：

- `CHANNELS_OPS_DATA_DIR`：数据目录。
- `CHANNELS_OPS_WORKSPACE_ROOT`：可导入素材的工作区，默认当前目录。
- `CHANNELS_OPS_PORT`：可选固定端口，默认 0（随机）。

宿主启动时注入私有数据目录、当前工作区和内部执行凭证。执行凭证不暴露给网页；普通网页请求不能核验平台身份、领取任务或写入平台结果。浏览器登录凭据留在宿主账号环境内。

## 操作状态

发布：`prepared → running → submitting → submitted / reviewing / published`。

`prepared` 只表示任务已准备；`submitted` 为平台接受提交；`reviewing` 为审核中；`published` 必须有页面证据。回复成功使用 `replied`。只读同步成功使用 `succeeded`。

只有 `prepared` 可以取消。相同草稿版本不能重复准备发布，即使更换操作标识。取消未执行任务后可以重新准备。已失败或已提交的版本不会自动重发；必要时明确核对后创建新内容版本。提交后结果不明为 `uncertain`，阻止同账号后续执行。服务重启将正在提交的任务恢复为待核对，绝不恢复为可重新提交。

SQLite 存储持久记录。每类记录最多 1000 条、账号最多 50 个；页面展示最近 100 条，草稿快捷列表展示最近 5 条。不存在全量统计承诺。数据中的 null 为未获取，0 仅表示观察到的零。同期不同作品的指标仅作最近已同步作品汇总，注明已获取数量。

素材限制为本地限制：MP4 512 MiB，PNG/JPEG/WebP 10 MiB。检查文件头并流式保存；此检查不等于完整视频解码或平台格式验证，真实发布按平台当前限制预检。工作区路径经 realpath 检查，拒绝越界。预览采用限时、单素材签名链接，支持视频范围读取。

## 验证与安装

```powershell
pnpm check
pnpm test
```

检查覆盖源码语法、清单版本、资源完整性。自动测试覆盖账号归属、身份与浏览器环境、草稿版本、素材内容与路径、并发领取、发布去重、结果状态、重启恢复、数据原子回写、HTTP 鉴权、媒体流及本地进程入口。进程入口测试使用模拟 runtime，不启动 iPolloWork。

浏览器验证采用单独的 `channels-preview` 会话及 `~/.ipollowork/plugin-data/wechat-channels-ops-preview` 数据目录。示例账号明确标为「本地体验」，没有平台身份、发布回执或虚构指标。验证覆盖扫码入口的本地/宿主状态、可见身份解析、真实 MP4/PNG 上传与预览、草稿保存刷新、准备任务去重，以及 390、768、1440 宽度下六个功能页的横向布局。截图与测试素材位于忽略的 `output/playwright/`，不进入插件包。

开发环境从本目录读取插件；桌面安装包把运行所需的清单、服务、技能和页面复制到 `plugin-packages/wechat-channels-ops`。用户在主软件插件列表安装或更新，不依赖 `~/.ipollowork/local-plugin-packages`。

## 代码归属与来源

`service/` 负责记录、素材、任务状态和本地/宿主入口；`ui/` 负责六个功能页面；`skills/` 负责平台操作与日程规则；`tests/` 与 `scripts/` 负责自动验证。没有对宿主源码的运行时导入，没有独立 AI 服务或第二个调度器。

本地服务/记录存储参考相邻社交运营插件，浏览器操作约定复用宿主现有能力。插件随桌面包携带运行文件，不依赖外部插件仓库。来源 iPolloWork（Different AI, Inc.），保留原 [LICENSE](LICENSE) 与 [历史 MIT 许可](LICENSES/MIT-legacy.txt)。
