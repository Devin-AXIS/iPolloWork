# iPolloWork 桌面端回归测试用例

以 `Jovan` 分支提交 `a8c1d5b7f` 为设计基线。首轮在 Windows x64 Electron 上验证安装、首次任务、会话恢复、权限、扩展和交付物。发布到其他平台时，使用对应的实际安装包复跑受影响的用例。Cloud、组织自建服务、MCP 和外部引擎用例需要各自的测试环境。

## 执行环境和测试数据

| 编号 | 准备内容 |
| --- | --- |
| E1 | Windows x64 测试虚拟机，保存从未安装 iPolloWork 的快照。准备候选安装包和上一受支持版本，记录包版本、提交、OS 版本和架构。 |
| E2 | Electron 开发实例，使用独立测试配置和目录。准备启用 OpenCode 的项目以及按需启用 Codex、DeepSeek Harness 的项目。记录引擎版本、实际选择的模型及权限模式。 |
| E3 | 测试 Cloud 或组织自建服务。准备两个隔离的企业组织，具备组织管理员、普通成员及模板／插件／技能管理员角色。测试 MCP 使用沙盒账号或仓库模拟 OAuth 服务。 |
| D1 | 在个人身份及两个企业身份下建立独立测试项目。每个项目放一份同名的 `qa-marker.txt`，内容分别为 `QA-PERSONAL`、`QA-ORG-A`、`QA-ORG-B`。另外准备 `QA 项目 A` 和 `QA 项目 B`，供项目间切换与日程测试使用。 |
| D2 | 固定文本 `请只回复 QA-<本轮编号>`，以及可分段、延迟、失败和恢复的测试模型响应。模型联调检查响应标记、消息数量、工具副作用和任务归属。 |
| D3 | 一页有效 PDF、可编辑的三页 PPT 模板、带本地图片的 HTML、带中文标题的 Markdown、短音轨和视频测试工程。为待编辑文件记下原始路径、大小和 SHA-256。 |
| D4 | 100 MB 与 200 MB 两组附件，各自生成比上限少 1 字节、等于上限和多 1 字节的文件，见附件用例。准备可用的插件 v1.0.0、v1.1.0 与损坏的更新包。 |

运行前记录账号角色、项目和会话标识。涉及升级、恢复配置或权限变更的用例使用测试快照。用于断网、超时和迟到事件的用例从隔离环境注入故障。真实模型和真实服务的联调结论单独记录。测试账号、项目、插件状态与输出目录按用例恢复。

## 优先级和执行顺序

- **P0** 是适用发行范围的放行项。覆盖首次可用、数据和权限隔离、升级保留数据，以及发行包承诺的核心交付能力。
- **P1** 是功能回归项。模块改动时执行该模块的所有适用用例，覆盖失败、恢复、边界和并发。
- **P2** 是扩展兼容性和性能用例。根据候选版本的改动范围和支持平台选择。
- 日常提测先跑 `BOOT-01`、`CHAT-01` 和 `CHAT-02`。发布验收再执行适用的 P0、改动模块的 P1，以及对应平台的安装包验收。没有专用测试前置条件时，每条用例从清洁状态独立执行。

## 会话和附件

### CHAT-01 首条消息和流式完成

**P0 · Electron · E2、D2。** 使用已完成引导的项目，模型设置为分两段发送固定标记。

| 步骤 | 预期结果 |
| --- | --- |
| 1. 在项目内新建任务并发送标记。 | 当前路由和侧栏指向新会话，记录中出现一条本次用户消息。 |
| 2. 第一段返回后观察回复区，随后释放剩余文本和完成信号。 | 回复在同一位置增长，进度状态最终收敛，最终标记完整且只出现一次于该助手回复。 |
| 3. 离开会话再进入，核对任务和消息。 | 同一会话仍有一条用户消息和一条对应的完成回复，顺序与内容一致。 |

### CHAT-02 完全退出后恢复会话与文件

**P0 · Electron · E2、D2、D3。** 项目 A 的已完成会话有明确标记和一份保存的文件。项目 B 有另一条会话。

| 步骤 | 预期结果 |
| --- | --- |
| 1. 记录项目 A 会话标识、末条回复和文件哈希。完全退出 iPolloWork 后重新启动。 | 应用可进入原项目 A，并能从历史打开同一会话。回复和文件仍可读。 |
| 2. 从会话内打开文件，再切换到项目 B。 | 文件哈希与原值一致。项目 B 只展示自己的会话与产物。 |
| 3. 回到项目 A 并发送新的标记。 | 新消息追加到原会话，旧消息和文件卡片保持原归属。 |

`core-flow` 使用页面重载证明渲染层恢复。本用例的完全退出和进程重启需要独立验证。

**P2 · 实际安装包 · E1、D2、D3。** 同一机器及测试配置对比候选版本和上一受支持版本。记录 CPU、内存、磁盘、显示缩放和引擎。

1. 两个版本各采集 10 次冷启动，从启动进程计时到输入框可编辑。另在一个包含 100 条固定消息的会话采集 10 次切入至末条消息可见的时长。
2. 连续 20 次在两个会话之间切换并打开、关闭同一份 PDF，记录首次与末次可操作时间、Electron 进程组内存、界面错误和崩溃。
3. 汇总两版中位数、最大值和原始样本。时间和内存按发布时约定的预算判定。没有正式预算时保留对比结果。出现崩溃、界面挂起或任务无法继续时记录为失败。

## 结果记录和发布判定

| 用例 ID | 环境／构建 | 数据或会话标识 | 实际结果 | 状态 | 证据或缺陷 |
| --- | --- | --- | --- | --- | --- |
| 例 `CHAT-03` | Windows x64、候选构建 | 项目 ID、会话 ID | 记录异常发生的步骤、状态和实际消息数 | 待执行 | 截图、脱敏日志或 fraimz 路径 |

- 状态用“待执行”“通过”“失败”“阻塞”“不适用”。缺少模型、账号或专用环境时记录为阻塞，列明缺少的条件。Runner 的跳过结果按原因转为阻塞或不适用。
