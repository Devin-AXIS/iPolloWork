# DSH 0.2.3-alpha.2 升级验收

[English](dsh-alpha2-validation-2026-11-23.md) | 中文

真实安装打包已通过应用保护并运行到 Office 发现检查。alpha.2 将三个格式专用教程合并为单一 `office` 技能，冒烟改为加载该原生条目；仍须执行真实 DOCX/XLSX/PPTX 转换、图片渲染及表格重算检查。

产品候选版本 1.0.16，Suite 0.1.51，账号服务 0.1.19；官方 DSH 源码固定为 `4b399c39a6d1479cd84ca591b4d7c88e24d38a96`。本文按《iPolloWork_DSH升级影响分析_简版_2026-11-23》的风险类别记录实际检查，文档中的潜在影响不等同于已发生故障。

实际需要修正的变化包括 Node 24.22.3 与 SDK/Cordis/Schemastery 版本、账号工程路径、模型图片参数、MCP 探测入口、客户端 settings 类型声明、Include 返回结构与条目校验，以及桌面原生设置的配置归属。嵌套 Include 会令教程和通知设置无法编辑；现由私有 Bundle 在原生 profile 树挂载原有条目，保留 ID 和偏好。运行时根清单声明 Suite，恢复原生解析。线上旧市场目录不再覆盖更高且兼容的新内置版本。

候选套件完整检查 244 项通过、11 项专用原生环境用例跳过；Windows 桌面 310 项通过、5 项平台或原生环境条件用例跳过；根工具链在完整 npm 环境下 31 项全部通过。独立原生安装与真实桌面验证另行执行，不把跳过项计为通过。外部账号、真实第三方消息和付费生成均保留其明确边界。

发布打包发现 Xcode 26.3 / Swift 6.2.4 无法编译新版原生电脑操作程序。官方同版本发布包的辅助程序源码摘要与当前 pin 一致，打包改为严格校验该产物后重新签名、公证和运行协议回归。Linux 安装冒烟同时纠正旧的“条目不可寻址”断言，验证本次适配所需的原生可编辑设置及必需 Bundle 保护。真实平台安装包、签名与公证仍是发布前独立闸门。

Windows 和 Linux 的真实安装冒烟随后发现，仅将产品设置平铺会失去私有应用 Bundle 的管理保护。现使用 profile 相对路径及公开 `initial: []` 的启用原生 Include 恢复管理边界，偏好仍保留在可编辑根配置。隔离原生管理器实测确认停用返回 `management-required`、卸载返回 `not-removable`，产品安装包冒烟保留这两项检查。两种 Mac 架构均已通过调整后的辅助程序签名和公证步骤；完整重建安装包仍待验收。

日常配置还发现历史 Design `link:` 依赖指向旧开发目录。原生安装的兼容性检查拒绝旧版本并自动回滚；通过原生管理器移除这条依赖后，新归档正常安装。以后升级先盘点 `link:` 与归档来源，分别走原生移除和安装，不改用户开发目录，也不添加版本豁免。

发布前审计发现官方依赖图中的 MCP server 2.2.0 命中已公布的漏洞（[跨客户端消息](https://github.com/advisories/GHSA-jm63-cq47-j5jp)、[内存耗尽](https://github.com/advisories/GHSA-46jr-4wx8-v453)、[令牌受众校验](https://github.com/advisories/GHSA-rvq5-wwqv-78pq)）。产品运行时、桌面打包和云运行时约束固定修复版本 2.4.0，Suite 测试依赖同步更新；四份产品锁文件审计均为零漏洞。该约束不改官方源码或其固定锁文件。

干净检出检查读取受版本控制的业务清单，核对实际发货归档中的资源，不依赖本机生成的 JavaScript。小红书子进程用例创建独立的已打包运行时样例，验证 Electron 的 Node 模式和退出清理，不连接网络安装依赖。

后续升级必须更新固定版本、重建并核对真实归档、跑版本契约和源码不可变检查，再在真实 Electron 验证设置可写、首次配置、教程、插件打开和进程存活。Studio 来源与适配补丁由 `integrations/runtime/studios.json` 记录，可用 `npm run prepare:studios -- <干净源码目录>` 复现。官方 `.upstream/dsh` 不承载产品修改。
