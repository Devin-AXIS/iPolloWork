# Mac 1.0.9 登录及升级界面诊断

## 用户现象和证据边界

- M 系列 Mac 安装 1.0.9 后，英文登录窗口提示邮箱或密码错误；同一账号密码能在 `cloud.ipollo.net` 网页登录。
- 部分之前已登录的用户更新后，直接进入基础 DSH 界面。
- 本次未取得出问题设备的本地配置和完整登录请求日志，因此不能断言某一次密码提示对应的实际云端拒绝原因。

## 已复现的代码问题

1. 官方 `initProfile` 仅首次创建清单。桌面旧配置已存在时，必需的 `@ipollo/desktop-host` 不会补入 Bundle 列表；公开 Suite 等历史条目也可能与私有应用组合竞争。新增旧配置回归测试在修复前失败，修复后通过。
2. 1.0.9 仅备份版本冲突的 DSH 核心包，没有处理 profile 中的产品包。产品旧副本或相同 SDK 版本的私有 Host 仍可能覆盖安装包拥有的实现。
3. 欢迎窗口将 `IPW_SIGN_IN_REQUIRED` 归类为密码错误；正确凭据提交后的会话校验拒绝，也可能显示同一错误。历史配置还可能关闭产品主题／账号或改变服务地址。

## 修复

- 使用官方 profile 清单及启动入口补齐私有 Host，移除重复产品 Bundle 和直接依赖；先保存原清单，只改变产品拥有的条目。
- 按安装包清单备份冲突产品副本，并恢复安装包内的实现；不修改 DSH 解析器，不清空用户数据。
- 最后一个原生 Include overlay 启用产品应用入口。私有发行版根据 install-anchor 包身份固定账号、主题及 `https://cloud.ipollo.net`；其他配置保持原值。
- 进入工作区前核验产品组件；登录提示分别表示密码错误、会话拒绝、服务不可用、超时及限流，不展示原始敏感响应。

## 验证记录

- 使用专用合成账号，真实云端注册、正确密码登录、邮箱大小写归一化及错误密码分类通过。未使用或索取用户密码，也未调用模型。
- 桌面类型检查通过；新增旧配置迁移、应用 overlay、产品包恢复及错误分类回归通过。
- Mac 签名安装包增加实际登录、旧配置升级、保存登录后重启，以及相同版本 Suite 冲突恢复检查。安装包构建和实际运行结果以对应发布流水线及其截图／结果文件为准；编写本文时尚未完成该阶段。

所有修复位于产品仓库；固定 DSH 源码保持不变。没有为此次修复重新部署账号服务或更改数据库。
