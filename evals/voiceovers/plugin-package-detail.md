# plugin-package-detail — Open a plugin and control its skills

1. I open Figma from the independent plugin list, and it now gets a calm dedicated detail view with the plugin identity, its application connection, and a clearly grouped skills section.

2. I switch off Design to Code, and only that skill changes to the off state while the rest of the plugin detail remains available.

3. I switch Design to Code back on, and the detail view confirms the skill is available again without leaving the page.

4. I install the upgraded Notion, Linear, Sentry, Stripe, and Context7 packages. Notion now opens as a complete service plugin with four managed skills and its existing MCP authorization flow.

5. I return to the plugin list, install the official GitHub package, and the list now shows GitHub alongside the upgraded service packages instead of hiding it from the development client.

6. I open GitHub as its own full detail page and can see one connected service boundary, four independently switchable skills, secure authorization, publisher metadata, version, and uninstall controls.

7. I return to the plugin list and use the visible Import Plugin action. The complete package flow asks for a plugin archive instead of making developers type an internal workspace path.

8. I select a developer archive, review its skills, agents, commands, and MCP counts, and the safety check confirms that no local service or host-process code will run before installation.

9. I install the inspected package, and it opens as its own plugin detail with publisher, version, skills, and an explicit uninstall action.

10. I uninstall the developer package, return to the plugin list, and the imported plugin is no longer present in the workspace.

11. I open the Video Agent and see its two managed skills separated from nine detected HyperFrames and media skills. The related list has no lifecycle switches, so the plugin explains the relationship without taking ownership or changing those independent capabilities.

12. I open the upgraded Figma plugin and see a clear connection and authorization section for the official Desktop MCP. Clicking connect now waits for the local service and shows either a connected result or an exact Desktop MCP setup message, instead of silently doing nothing or attempting unsupported remote OAuth registration.
