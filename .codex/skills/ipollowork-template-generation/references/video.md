# HyperFrames Video Rules

Use for `video`, including template application, custom generation and targeted edits. The active session's exact project, runtime, media actions and editor contract are authoritative. In the [shared guidelines](template-generation-contract.md#ipollowork-shared-creative-and-layout-guidelines), consult only sections 2–3 for scope/content, section 5 for layout selection, and section 7 for media. Read [video-motion-principles.md](video-motion-principles.md) once for initial generation or substantial scene redesign. Read [video-acceptance.md](video-acceptance.md) once before final validation; targeted edits run only its affected checks plus core playback. Do not load unrelated category guidance.

## Plan content and reuse

Read the brief, current `index.html`, template guide, tokens and existing assets. For initial/full generation, create a compact storyboard that gives every scene a purpose, visible content, narration intent, media need and approximate duration. For every substantive scene, include the compact narration beat map defined in `video-motion-principles.md`; it binds each spoken intent to a time range, visual focus, visual action, and result or hold. If the storyboard is not already confirmed and the user did not explicitly request direct generation, present it once before submitting media or composing the full timeline; do not request the same confirmation again. Content determines scene count and timing; sample counts and durations are not quotas. An explicit user maximum remains strict. For targeted edits, preserve unrelated scenes, media and user changes.

Read `core-v1-index.md`, `core-v1-video/catalog.md`, and `core-v1-video/motion/catalog.md` metadata once. Select the primary temporal pattern from the scene's narrative verb, then consult `core-v1-video/motion/component-map.md` for matching Video Studio components and secondary capability overlays. A component's default primary mapping does not prevent using it with another listed pattern when that pattern's recipe and acceptance conditions are implemented. Shortlist at most three scene bodies and three mapped components; open only selected sources and relevant guidance. For every substantive scene, record `scene → narrative job → motion pattern → component ID`, or a specific reason no listed component fits. Install the selected IDs in one call to `media/video_component_install` with the exact `video/<project-id>/index.html`; use the returned host-timed `data-composition-src` snippets, stable scene IDs, unique `data-composition-id` values, real `data-variable-values`, `data-ipw-registry-component`, `data-motion-pattern`, `data-ipw-timing-source`, and executable `data-ipw-beats`. Do not redraw, paraphrase, or imitate a mapped component after selecting it. A custom scene must declare `data-ipw-component-decision="custom:<specific structural reason>"`; visual preference alone is not a sufficient reason. Read `shared-contract.md` once before implementation, not once per scene. Reuse fitting spatial and temporal references or write a new composition in the active visual language only when none fits. If references or the install action are absent in an older session, inspect actual local files and record the missing capability instead of inventing paths or pretending a component was reused.

Video layouts describe spatial content slots, not complete compositions, timelines, narration or required scene duration. Give each substantive scene a temporal story pattern and observable Establish, Develop, and Land states under the motion principles. Never import PPT page roots or website responsive behavior into a video scene.

## Composition and timing

- Keep one authoritative root composition, its identity, declared stage dimensions and registered timeline. Use unique scene/clip IDs and supported editor hooks.
- Mark every full `.scene.clip` with `data-ipw-scene`. Its beat map uses scene-relative seconds, covers the complete scene without gaps or overlaps, and ends at the declared duration. Every beat binds stable `targets` to an executable `component:`, `preset:`, `custom:`, or explicit `hold:` animation reference. Keep full scene windows contiguous.
- Every scene after the first declares one incoming transition, duration, and narrative intent. Use a direct `cut` or an actual supported preset applied through `mutate_motion`; keep the returned `data-ipw-animation-reference`. Run the transition inside the incoming scene rather than overlapping full scene windows or fading the outgoing scene to empty.
- Keep mounted registry components host-timed. Preserve `data-ipw-timing-owner="host"` on the returned snippet, set the parent host to the actual scene duration, and let a completed component hold its Land state until that host ends. Never restore clip timing on the installed component root.
- Never delete or truncate the active `index.html` or `design-tokens.css` before its replacement is complete. Update in one operation, or prepare a sibling file and atomically rename it over the destination. A failed or interrupted edit must leave the last valid entry in place.
- When adding, removing, reordering or retiming scenes, synchronize the root duration, scene windows, clips, transitions, captions, audio and animation timestamps. Preserve these values for theme-only or unrelated edits.
- Use the session's FPS and quantize authored boundaries to integer frames. Serialize seconds with only the precision needed to represent `frame / fps`; do not accumulate independently rounded decimal durations. Sample reading time is planning input, never a replacement for measured audio.
- Drive movement through the existing paused, registered GSAP/HyperFrames timeline. Ensure direct seeking and replay are deterministic; no ambient CSS loops, wall-clock timers, random values or independently running timelines.
- For music-led `audio-reactive` scenes, mount the real local audio first and call `media/video_audio_analyze` once for the project entry. Select only meaningful returned onsets or sections, store them as literal scene-relative JSON in `data-ipw-audio-cues`, and bind every saved cue to an active beat motion window. Never infer cue timestamps from duration, filenames, or waveform graphics.
- Scope animation selectors to the actual scene instance. Fit entrance, readable hold and exit inside the scene window; incoming transition intervals must not obscure required information.
- Keep playback and audio sequencing framework-owned. Do not mute tracks or replace narration/music merely to avoid a preview problem.

## Visuals, assets and narration

The template owns typography, palette, graphic language and motion style. Apply theme tokens to scene styling; keep timing/tracks outside `design-tokens.css`. Compose for the declared stage and aspect ratio; change geometry intentionally for a different target, never through viewport-dependent reflow.

Follow shared asset/model rules and the active image/video generation Skills. Call `artifact_media_review phase=plan` once with the complete storyboard needs, reuse its capability result, and resolve one compatible model choice for each media operation. Reuse available files first. Submit independent assets as one bounded batch or in parallel when supported rather than serially blocking scene authoring. Save completed files under the current project's `assets/` and use project-relative paths. For asynchronous generation, query status/recovery before retrying; never duplicate a submission whose state is merely uncertain. Call `phase=check` once after placement outcomes settle.

Follow `ipollowork-video-voiceover` and the injected voiceover contract for enablement, authorized/default voices and validation. Preserve an explicit disabled choice. Without authorized narration, continue visual work, set affected scenes to `data-ipw-timing-source="estimated-reading"` or the actual silent timing source, and report that the result is silent. Do not redirect the user to Media Studio, block file generation, leave a pending-model placeholder, or invent audio files. When narration exists, use actual returned duration, set `data-ipw-timing-source="voiceover"`, and shift dependent beats, captions and transitions together; do not accelerate speech or omit facts to force sample timing.

## Editability and acceptance

Keep `data-composition-variables` literal, statically parseable and aligned with stable manifest IDs; preserve fixed-brand assets and editor hooks. Save the complete composition once and let the client run its aggregate component, project, and voiceover validation. Treat `valid=false`, a missing installed source, a missing motion pattern, or an unrecorded custom decision as a failed delivery during that client-owned gate. Follow `video-acceptance.md` as the single owner of visual, temporal, playback, audio, and export verdicts; do not start a second validator or preview loop from the model turn.
