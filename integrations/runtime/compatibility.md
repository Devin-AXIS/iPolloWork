# DSH compatibility record

English | [中文](compatibility.zh.md)

The [runtime pin](upstream.json) defines the DSH baseline: `dsh-v0.2.3-alpha.2`, source `4b399c39a6d1`. The records below also retain verification against `dsh-v0.2.2-rc.3`; those historical results must not be treated as validation of the new runtime. Commit `4c696c2b33` separated DSH from the product source tree. Earlier migrations are covered by the [existing upgrade guides](../../docs/upgrade-guide).

## Features to verify when upgrading

Video `1.0.0-beta.27-ipollo.3` passes FFmpeg and FFprobe settings to the owned HyperFrames preview process that handles export. The [Studio adaptation](studio-alpha2.patch) uses system tools when available and otherwise verifies the pinned executables in the DSH download cache. On the next pin, export an MP4 with audio from a fresh Windows and macOS profile whose GUI `PATH` has neither tool, repeat with the cached tools offline, and confirm explicit paths still work.

Design 1.0.0-beta.39-ipollo.4 reads the editor entry returned by document activation, including when the DSH file card or sidebar resource provides an absolute Windows path. Its [Studio adaptation](studio-alpha2.patch) also opens editable HTML when a CSS or script dependency is missing and preserves the original link on save. On the next runtime pin, generate a PPT in a new Windows workspace conversation, open it from both the filename and Edit actions, and verify slide rendering, version history and save even when the HTML references a missing theme stylesheet. Repeat with a selected slide template and its existing assets.

Design and Video each ship the same reference Skill. The [Studio adaptation](studio-alpha2.patch) gives each bundle a provider registered through `ctx.skills.registerProvider`. DSH resolves both contributions under the existing name `ipollowork-reference-analyzer`. Verify loading the full Skill body with each Studio installed alone and with both active. Disable one Studio and verify that the remaining provider still resolves the Skill. The default market excludes the standalone Reference Context, DeepSeek Harness and Plugin Workshop bundles, including stale service-catalog entries. Their verified archives remain available for migration of existing installations.

Desktop update feeds identify the target DSH and the reviewed archive identities from the same packaged source. The shell uses DSH's native manifest compatibility evaluator before confirming installation and rechecks the profile after locking new Host requests. An enabled third-party bundle or local link with unmet requirements blocks the handoff. A disabled incompatible bundle is listed before confirmation. A client upgrade without a preflight handoff reconstructs one from the installed catalog for enabled, incompatible, market-managed archives. It retains local links and newer versions. The next version's Host verifies each archive and runs the native locked package command with activation changes disabled. If one archive cannot be verified or installed, the handoff remains available for retry while other migrations and native workspace startup continue. Recheck legacy upgrades without a handoff, cache identity, version and digest binding, startup and retry after a damaged archive, and byte preservation of user patches and data on each new runtime pin.

The Short Video Studio preview cache is scoped to its workbench view and uses the existing `asset-read` action and `ui/resource-teardown` bridge message. On a new DSH pin, open a shipped workbench from the native plugin manager and verify image preload, explicit audio/video preview, project/view switching, and iframe teardown without interrupting a background generation job.

Alpha.2's `skill-office` provider publishes one `office` skill covering Word, PowerPoint and Excel; the separate `office-docx`, `office-pptx` and `office-xlsx` entries are retired. Desktop packaging must list and load the consolidated skill through the native registry. The smoke still converts all three real document fixtures to PDF, renders images, converts to OpenDocument and recalculates XLSX. Verify the provider's current catalog and these real operations together on the next pin.

Mac packaging consumes the official published `dsh-cua-macos` helper after matching the locked archive SHA-512, exact SDK package version, `cuaHelperSourceDigest` and both application generations through `verifyCuaHelperPayload`. Product packaging calls the pinned `build_app.py` publication function to apply its own Developer ID, notarizes and seals the new generations, rereads their selected paths, and runs the host architecture's official `protocol_e2e.py`. Official implementation bytes remain unchanged. Recheck these build-tool interfaces and the real Mac signatures/protocol on each pin.

Desktop keeps product settings in the editable profile root and inserts one active native Include as the private application's management boundary. Its profile-relative `./ipollowork-desktop-management.yml` uses the public `initial: []` option, so the native loader creates an empty configuration without moving product preferences into another tree. The native manager therefore rejects Bundle disable with `management-required` and removal with `not-removable`. Actual installed-runtime smoke verifies both rejections and editable product settings. Recheck these public protection rules on every pin; do not mutate the SDK's protected-plugin set or weaken the smoke assertions.

The alpha.2 migration aligns Node.js (`^24.22.3 || >=26.13.1`), Cordis (`4.2.0-alpha.1`), Schemastery (`3.20.0-alpha.1`), owned SDK peers and the private desktop Host version. The DeepSeek account project reference moved from `credentials` to `account`. The model profile now supplies `maxImageBytes` and `requestImageBudgetCount`; MCP probing uses public `McpClientHost.probe`. Product source checks, desktop types, native source staging, model/board/MCP contract tests and official portable-runtime checks passed in an isolated candidate. Final installed-archive checks, external-account checks and release deployment remain separate gates.

Windows setup verifies an exact Git commit and tree without file symlink privileges. Configuration copies are hash-managed. An explicit `--upgrade-upstream` retains the previous verified cache; setup refuses modified official source or silent pin replacement. A temporary short junction lets the unchanged official Python wheel/office checks run below MAX_PATH. `npm test` covers Node rejection, immutable checkout and junction cleanup; `check:upstream` rejects mixed SDK versions before packaging.

The optional nine-step beginner tour uses native `configForms`, `settings.section` and `shell.overlay`. It saves only tutorial progress, preserves previous initialization choices, resumes an unfinished tour, allows retry and local dismissal, and does not send messages or create projects. Locating an entry only focuses or scrolls it; unavailable entries have readable guidance. Check first-run handoff, settings restart, a delayed progress response after dismissal, both languages, themes and constrained windows on each runtime update.

Service schema 22 is an existing product migration, not a new DSH schema. Build copies every migration through the exported service schema constant. Deployment reads the target version from the built image instead of assuming schema 21; verify backups, forward migration and post-cutover readiness against the actual server before declaring deployment complete.

The first-run and restart loading branches share `plugins/ipollowork-suite/src/client/onboarding/OnboardingSurface.tsx`. The existing `shell.overlay` entry uses the public `IconLoadingOutlineRegular` and the DSH theme label color. On the next pin, hold the settings or account read pending during desktop startup and verify the centered indicator, titlebar clearance, light and dark themes, reduced motion and disappearance when the read settles.

Their additive Cordis entries join the private Host application under the native install anchor. On the next pin, package both registry and local bundles, verify relative entry resolution and duplicate-ID rejection, then open the installed application with a disposable profile and repeat an upgrade after changing a plugin preference.

Actual Electron cold-start exposed two configuration changes: `group: true` now requires an array, and native ConfigEditor only edits the profile's own tree; nested Includes own separate settings. Desktop therefore inserts its application entries directly through its private Bundle, preserving the existing entry IDs and saved preferences. Its final overlay only keeps Suite enabled. The runtime root explicitly declares the shipped Suite dependency so alpha.2 can resolve these native profile entries. The regression validates real Loader options and retained profile settings; real Electron verifies Suite `/info`, tutorial and notification settings discovery, all nine tutorial steps, saved progress after refresh and dark constrained layouts. Private Host dependencies must name the currently shipped Suite version, enforced before packaging.

Desktop `integrations/desktop/src/web-document.ts` withholds HTTP workbenches' `Origin-Agent-Cluster` header from `dsh-app://` responses. XHS's `?1` header triggered Chromium's `AddOriginAgentClusterStateForBrowsingInstance_Cpp` check in Electron 44.7.0, terminating the browser process with `0x80000003`; HTTP-browser checks do not cover this difference. CSP and CORP remain intact, and the HTTP Host response is unchanged. On desktop/Chromium upgrades, verify first open, reopening after panel switches, account dialogs and process survival in the actual desktop; a successful backend `open-workbench` call is insufficient. XHS workers explicitly inherit Electron's Node mode. Canvas awaits its latest model-context update before handing off an AI draft.

The XHS and WeChat Official imperative account forms remain native HTML dialogs inside their owning frame; moving them to the parent loses both business CSS and document-bound handlers. Their tokens, focus, Escape, scrolling and close buttons must be rechecked. XHS packaging rejects stale generated public assets. Legacy link buttons preserve their anchors. The desktop Host bundles JS emitted by `tsc -b` with `tsconfig: false`, avoiding a second project-reference traversal in the bundler; verify the built Host, package exports and real account/profile startup after a toolchain upgrade.

The ported UI adapter maps legacy button variants to supported native variants and transfers legacy dialog titles into `Modal.title`. Its scoped portal CSS is mounted in the parent document and released after the last owner; verify one accessible heading, native confirm/cancel buttons, full-width form fields and overlay disposal. Bulk development-profile installation may temporarily disable the generated HMR plugin through `-NoNativeHmr`; use the native Plugin Manager's restart-required path, then restart normally to restore HMR. Do not mutate package selections manually or patch upstream.

See [the upgrade diagnosis](../../docs/diagnostics/2026-11-20-mac-login-and-upgrade.md).

The official-model proxy replays a gateway invocation with the same request ID only when the connection fails before response headers or the gateway reports that invocation still running. Recovery is bounded, cancellable and tied to the account generation; native pi-ai retries remain disabled. Response-stream failures and unknown upstream outcomes are not replayed. The account service separately retries explicit chat HTTP 429 rejections inside one billing invocation. Recheck native streaming, prepared calls, cancellation, account changes and exactly-once settlement on the next DSH pin. The Design editor resolves authored CSS units to layout pixels before dragging/resizing, converts pointer deltas through parent scale, and requires real movement before guide snapping; verify imported PPT percentages, stylesheet positions, content-box sizing, anchored boxes and fixed-stage zoom.

Design `1.0.0-beta.37`, bundled with Suite `0.1.39`, uses native `ctx.skills.register`, `ctx.tools.register`, required `systemPrompt.context`, workspace ownership and sandbox policy for template authoring. The original editor resolves CSS units and theme variables before exposing pixel-based property controls; floating element actions select the Element tab. The enterprise VI template retains default geometry while consuming theme tokens, and fixed native-slide layouts hide unsupported global geometry controls. PDF yielding has a timer fallback for background windows. On the next pin, verify Skill discovery/loading, required model context, stale/read-only/foreign-workspace rejection, HTML card/link opening, local media, property changes, theme persistence, 38-page editable PPTX/PDF, both themes and 390px. See the [verification report](../../docs/design-template-fidelity-2026-11-19.md). The Agent and DSH sources remain unchanged.

The [MCP connection controls](../../plugins/ipollowork-suite/src/host/mcp-connections.ts) use native `mcpManager.list/restart` and revision-checked `settings.mutate` in the web-app's `mcp-manager` namespace. Editing opens the native Settings document. Organization disconnect choices stay on this device in the native credential provider, scoped by verified account identity and service origin. Existing installations without saved choices keep catalog-only discovery; resolving saved choices adds one identity read per account generation, never a balance request. Verify tool withdrawal, reconnect, refresh/restart persistence, account switching, stale revisions, failed saves, deletion confirmation, both themes and narrow settings panels. Native configuration editing and plugin-owned lifetimes must remain intact; no DSH source is modified.
