# DSH compatibility record

English | [中文](compatibility.zh.md)

The [runtime pin](upstream.json) defines the DSH baseline. This inventory covers `dsh-v0.2.2-rc.3` (source `39163dd30f70`), Jovan at `5104d080ba`, and the November 16, 2026 working changes. Commit `4c696c2b33` separated DSH from the product source tree. Earlier migrations are covered by the [existing upgrade guides](../../docs/upgrade-guide).

## Updating and verifying

Suite `0.1.36` and Design `1.0.0-beta.35` use the optional client service `ipolloDesignTemplates` to register organization template sources. Cordis injection/disposal controls the Organization Space template tab and clears account-scoped sources when credentials change. Metadata comes from the authorized account catalog; applying a template rechecks the exact version permission before creating a new Design document through `/document` and revision-checked `/file`. Verify Design disabled/enabled, two members with different grants, revocation, account changes and editing the resulting HTML. No organization credential is passed to Design.

Organization MCP uses the public native `mcpManager.list`, `register` and `restart` APIs. Its native settings section reads redacted status DTOs and refreshes current grants before reconnecting. Cloud runtime grants allow only the member catalog and connector transport methods; service-side membership and resource checks still authorize every call. Verify discovery, a real native Agent tool call, revocation and sign-out locally and in a cloud runtime. Organization model/tool dialogs use native Modal `contentClassName` and `footer` to keep long API routes scrollable and actions visible. Field styles target only direct raw inputs, preserving the native Add Plugin Input wrapper. Check both themes at 390px and verify publication errors distinguish missing metadata, invalid versions and conflicts.

1. Update both languages of this record in the same change as a DSH-dependent modification. Record the product entry point, upstream API or selector, how to verify it and the DSH version verified. When an upstream implementation replaces a local adaptation, record why it was retired and the first verified release.
2. Evaluate candidate DSH releases in a fresh worktree. Update the pin, manifests and lockfiles together, using the candidate's matching source and build outputs. Prefer public extension points and types. Probe optional host capabilities and resolve missing required interfaces before adopting the pin.
3. At the repository root run `npm run setup:build`, `npm test`, `npm run check:upstream` and `npm run check:docs`. Build, type-check and test affected packages. DSH supplies the plugin RPC and session archive types. Verify DOM, runtime events and packaged resources in a real client.
4. Follow the [desktop verification guide](../desktop/tests/README.md) in a disposable profile for the affected flows above. Record the candidate source revision, platform, results and coverage gaps. Passing on the current pin verifies that version only.
